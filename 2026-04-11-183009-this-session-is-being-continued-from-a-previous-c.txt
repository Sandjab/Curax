⏺ Parfait. Scope verrouillé :
  - Extraire main() en sous-fonctions (une par commande CLI)
  - Unifier les 4 fonctions dedup_* en une ou deux fonctions paramétrées
  - Supprimer --migrate et migrate_to_catalog()
  - Aucun changement de comportement

  Voici 3 approches pour structurer le refactoring :

  ---
  Approche 1 — Extraction plate (une fonction par commande)

  Chaque branche de main() devient une fonction top-level :
  cmd_reclassify(args), cmd_reclassify_papers(args),
  cmd_regenerate_companions(args), cmd_import(args). main() ne fait plus que
  argparse + dispatch. Les dedup sont unifiées. Chaque cmd_* reste autonome — on
   duplique un peu le pattern "parallel scoring + progress", mais chaque
  commande se lit de haut en bas sans indirection.

  + Simple, lisible, chaque commande est indépendante
  - Le pattern ThreadPoolExecutor + progress est répété 5 fois

  ---
  Approche 2 — Extraction avec abstraction du workflow

  Comme l'approche 1, mais on extrait en plus un helper
  run_parallel_scoring(items, worker_fn, workers, label) qui encapsule le
  pattern ThreadPoolExecutor + as_completed + compteur de progression. Chaque
  cmd_* appelle ce helper avec sa propre worker function.

  + Plus DRY sur le pattern parallèle
  - Abstraction fragile : chaque commande a un traitement post-résultat 
  différent (domain validation, catalog update, change detection), donc le 
  helper devrait accepter un callback ou retourner les résultats bruts — gain 
  marginal

  ---
  Approche 3 — Extraction plate + unification dedup uniquement

  Comme l'approche 1, mais on ne tente pas d'abstraire le pattern parallèle. On
  se concentre sur les deux gains clairs : (a) main() passe de 647 lignes à ~20
  lignes, (b) 4 fonctions dedup deviennent 2. Le reste est du copier-déplacer
  mécanique.

  + Risque de régression minimal — c'est juste du déplacement de code
  + Les 5 patterns parallèles sont similaires mais pas identiques — forcer une 
  abstraction serait YAGNI
  - Légèrement moins DRY que l'approche 2

  ---
  Je recommande l'approche 3. C'est la plus pragmatique : le gain principal est
  la lisibilité de main() et l'unification dedup. Abstraire le pattern parallèle
   n'apporte pas assez de valeur par rapport à la complexité ajoutée — les 5
  instances ont des post-traitements différents, et une abstraction à base de
  callbacks serait moins lisible que le code inline.

  dedup_batch(items, fingerprint_fn) — Remplace dedup_files + dedup_pdf_files

  def dedup_batch(items, fingerprint_fn):
      """Dedup intra-batch. items = {path: content/text}. 
      fingerprint_fn(content) -> str|None. Retourne set des chemins exclus."""
      fingerprints = {}
      excluded = set()
      for filepath, content in items.items():
          fp = fingerprint_fn(content)
          if fp is None:
              continue
          if fp in fingerprints:
              excluded.add(filepath)
              print(f"  Doublon exclu : {os.path.basename(filepath)} ...")
          else:
              fingerprints[fp] = filepath
      return excluded

  Appelé avec :
  - Articles : dedup_batch(file_contents, extract_content_fingerprint)
  - PDFs : dedup_batch(pdf_texts, extract_pdf_fingerprint)

  dedup_against_catalog(items, excluded, existing_entries, fingerprint_fn, 
  content_reader, doi_fn=None) — Remplace dedup_against_catalog +
  dedup_pdfs_against_catalog

  def dedup_against_catalog(items, excluded, existing_entries, 
                            fingerprint_fn, content_reader, doi_fn=None):
      """Compare les nouveaux items au catalogue existant.
      existing_entries = {key: meta} du catalogue.
      content_reader(key) -> content pour calculer le fingerprint.
      doi_fn(content) -> str|None, optionnel (PDFs uniquement)."""
      existing_fps = set()
      existing_dois = set()
      for key, meta in existing_entries.items():
          content = content_reader(key)
          if content is not None:
              fp = fingerprint_fn(content)
              if fp:
                  existing_fps.add(fp)
          if doi_fn:
              doi = meta.get("doi", "")
              if doi:
                  existing_dois.add(doi.lower())

      catalog_dupes = set()
      for filepath, content in items.items():
          if filepath in excluded:
              continue
          fp = fingerprint_fn(content)
          if fp and fp in existing_fps:
              catalog_dupes.add(filepath)
              print(f"  Deja importe (fingerprint) : 
  {os.path.basename(filepath)}")
              continue
          if doi_fn:
              doi = doi_fn(content)
              if doi and doi.lower() in existing_dois:
                  catalog_dupes.add(filepath)
                  print(f"  Deja importe (DOI) : {os.path.basename(filepath)}")
      return catalog_dupes

  Appelé avec :
  - Articles : dedup_against_catalog(file_contents, excluded, 
  catalog["articles"], extract_content_fingerprint, article_reader)
    - article_reader lit le fichier HTML depuis PROJECT_ROOT et retourne son
  contenu
  - PDFs : dedup_against_catalog(pdf_texts, excluded, papers_catalog["papers"], 
  extract_pdf_fingerprint, pdf_reader, doi_fn=extract_pdf_doi)

  def _read_article_content(article_key):
      path = os.path.join(PROJECT_ROOT, article_key)
      if not os.path.isfile(path):
          return None
      with open(path, encoding='utf-8', errors='replace') as f:
          return f.read()

  def _read_pdf_text(paper_key):
      path = os.path.join(PROJECT_ROOT, paper_key)
      if not os.path.isfile(path):
          return None
      try:
          return extract_pdf_text(path)
      except Exception:
          return None

  Critique

  C1. Onglets sans semantique ARIA
  - Localisation : index.html:42-49, style.css:296-335
  - Categorie : Accessibilite
  - Description : Le tab bar (#tab-bar) n'a pas role="tablist". Les boutons
  n'ont pas role="tab", aria-selected, ni aria-controls. Les panneaux
  (#tab-articles, #tab-publications) n'ont pas role="tabpanel" ni
  aria-labelledby.
  - Impact : Les lecteurs d'ecran ne reconnaissent pas la navigation par
  onglets. Les utilisateurs clavier ne peuvent pas naviguer avec les fleches
  gauche/droite (pattern ARIA tabs standard).
  - WCAG : 4.1.2 Name, Role, Value (niveau A)
  - Recommandation : Ajouter les roles ARIA + navigation clavier fleches. C'est
  deja la tache #4 du TODO.
  - Commande suggeree : /harden

  C2. Pas de lien skip-to-content
  - Localisation : index.html:18 (debut du body)
  - Categorie : Accessibilite
  - Description : Aucun lien d'evitement pour sauter directement au contenu
  principal. Un utilisateur clavier doit traverser header + theme controls +
  tabs + search + filtres avant d'atteindre le premier article.
  - Impact : Penalisant pour les utilisateurs clavier et lecteurs d'ecran,
  surtout avec 412 elements focusables.
  - WCAG : 2.4.1 Bypass Blocks (niveau A)
  - Recommandation : Ajouter <a href="#content" class="skip-link">Aller au 
  contenu</a> en premier enfant du body, visible au focus.
  - Commande suggeree : /harden

  Haute

  H1. Contraste liens sur cartes — AstroVista
  - Localisation : themes.js (theme astrovista)
  - Categorie : Theming
  - Description : Ratio de contraste des liens sur fond carte : 3.25:1 (light)
  et 4.33:1 (dark). Le minimum WCAG AA est 4.5:1.
  - Impact : Titres des articles difficiles a lire sur ce theme.

  Les 3 themes restants (Portfolio, Sage Green, Offworld) ont chacun une
  personnalite propre. C'est un outil de curation qui ressemble a un outil de
  curation, pas a une landing page SaaS.

  Impression generale

  Curax ressemble a un wiki de curation bien tenu — sobre, dense en information,
   sans distraction. Le theme Portfolio donne un ton "bibliotheque personnelle"
  agreable. La recherche et les filtres fonctionnent bien. Le plus gros probleme

  Issues prioritaires

  1. La page est un tunnel sans fin

  Quoi : 261 articles = 49 354px de scroll vertical. Certains domaines ont 50+
  articles dans une grille 3 colonnes. On tombe sur des ecrans entiers de beige
  sans contenu visible pendant le scroll.

  Pourquoi : L'utilisateur perd sa position. Impossible de "scanner" les 9
  domaines — il faut scroller pendant 30 secondes pour atteindre le bas. La
  corbeille (articles < 5/10) est invisible sans effort delibere.

  Fix : C'est le TODO #5 (pagination/virtualisation). A court terme : replier
  les domaines au-dela de la premiere rangee de cartes avec un bouton "Voir les
  N articles" par domaine. Ca reduirait la hauteur de page de ~80%.

  Commande : /optimize

  2. Le bloc Observations est trop long

  Quoi : Le paragraphe "Analyse du corpus" fait ~6 lignes denses. Il occupe la
  moitie du viewport au chargement, repoussant les cartes en dessous du fold.

  Pourquoi : Le contenu le plus utile (les articles) est invisible sans
  scroller. L'observation est interessante mais secondaire — c'est un editorial,
   pas le contenu principal.

  Fix : Deux options : (a) le rendre collapsible avec juste la premiere phrase
  visible, ou (b) le deplacer en sidebar ou en footer de section. Option (a) est
   la plus simple.

  Commande : /distill

  3. Les descriptions de domaine sont trop longues

  Quoi : Sous chaque titre de domaine (ex: "Recherche & Publications IA"), il y
  a une description d'une a deux lignes qui repete le contenu du titre en plus
  verbeux.

  Pourquoi : Bruit visuel. Les descriptions sont generees par Claude et sont
  souvent redondantes avec le titre + emoji. Elles ajoutent du scroll sans
  valeur.

  Fix : Soit les raccourcir a max 10 mots, soit les supprimer et laisser les
  emojis + titres parler. L'icone + le titre suffisent a comprendre chaque
  domaine.

  Commande : /quieter

  4. Les tags sur les cartes sont tres petits et peu utiles

  Quoi : Les tags (mcp, skills, orchestration) sont affiches en 0.7rem sur les
  cartes dans des pills gris clair. Ils sont quasiment illisibles.

  Pourquoi : Si les tags sont assez importants pour etre affiches, ils doivent
  etre lisibles. Sinon, les masquer. En l'etat, ils occupent de l'espace sans
  etre exploitables.

  Fix : Soit agrandir a 0.8rem avec un contraste plus fort, soit les masquer par
   defaut et ne les afficher que dans le panneau filtres (ou ils sont deja
  cliquables et utiles).

  Commande : /quieter

  - Et si les filtres etaient toujours visibles (sticky) ? Sur une page de 49k
