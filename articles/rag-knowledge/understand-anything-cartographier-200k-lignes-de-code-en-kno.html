Stop Reading Code Blind. How Understand Anything Maps 200k Lines Into a Graph You Can Actually Explore.

After 6 min reading, you will know how to generate interactive maps of any codebase using Understand Anything , how its 7-agent pipeline works, and exactly how to get started in 30 seconds.

Here's all you need to know about understand-anything and get started.

The Problem

The problem is well-documented. You join a new team. The codebase is 200,000 lines. Documentation is stale or missing. The one engineer who understood the auth flow left six months ago.
You are reading code blind.
Existing tools solve parts of this. Sourcegraph gives you cross-repo search. Greptile gives you semantic Q&A over your codebase. GitNexus gives AI agents graph-aware context via MCP. DeepWiki generates natural-language summaries of public repos.
None of them give you a visual, interactive, shareable, agent-integrated knowledge graph. One that covers structural analysis, business domain mapping, guided architectural tours, and knowledge-base analysis in a single plugin workflow.
That is the gap Understand Anything is targeting.
The new version shipped last week, latest as of May 25, 2026. The project has 36 contributors, 2.4k forks, TypeScript-first.
It runs natively on Claude Code and has one-line install support across 14 other platforms including Cursor, Gemini CLI, and Copilot.

What Understand-Anything Actually Does

You point it at your project and run /understand. A multi-agent pipeline scans every file, extracts every function, class, import, and dependency, and assembles it into a knowledge graph saved as JSON.
Then you open the dashboard and see the entire thing laid out visually, color-coded by architectural layer, searchable, clickable.
It's not a diagram that wows you with how complex your codebase is. It's a graph that quietly shows you how every piece fits together, in plain English.

Complete Walkthrough 10 Mins

Step 1: Install the Plugin
Open Claude Code in your terminal and run:
/plugin marketplace add Lum1104/Understand-Anything
/plugin install understand-anything
That's it. No npm installs, no config files, no environment setup.
If you're on Cursor, VS Code + Copilot, or another AI IDE, use the one-liner installer instead:
bash
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/Lum1104/Understand-Anything/main/install.sh | bash

# Windows (PowerShell)
iwr -useb https://raw.githubusercontent.com/Lum1104/Understand-Anything/main/install.ps1 | iex
You'll be prompted to pick your platform like codex, cursor, gemini, vscode, etc. The installer clones the repo to ~/.understand-anything/repo and creates the right symlinks. Restart your IDE after.
Step 2: Navigate to a Project
Pick a real codebase you've been meaning to understand. If you want a reference example, the repo itself links to a
microservices-demo fork
with a pre-committed graph you can explore immediately.
For this tutorial, let's assume you're working on your own project.
cd ~/my-project
Open Claude Code in this directory.
Step 3: Run the Analysis
/understand
This kicks off the multi-agent pipeline. Five agents run in parallel:
  • project-scanner - Discovers all files, detects languages and frameworks
  • file-analyzer - Extracts functions, classes, imports; builds graph nodes and edges
  • architecture-analyzer - Identifies architectural layers (API, Service, Data, UI, Utility)
  • tour-builder - Generates guided learning tours ordered by dependency
  • graph-reviewer - Validates graph completeness and referential integrity
File analysis runs in batches of 20–30 files, up to 5 concurrent. On a mid-sized repo, expect a few minutes.
When it's done, you'll have a .understand-anything/knowledge-graph.json file. This is your map.
Step 4: Open the Dashboard
/understand-dashboard
An interactive web dashboard opens in your browser.
GIF
Here's what you're looking at:
  • Nodes = files, functions, classes. Color-coded by architectural layer.
  • Edges = dependencies and relationships between them.
  • Click any node to get its code, its relationships, and a plain-English summary.
  • Search bar supports fuzzy and semantic search. Type "auth" and get every node related to authentication, even if the word doesn't appear in the filename.
Try clicking around. Navigate from an API endpoint down to the service it calls, then to the database layer it touches. You just traced an entire call chain without reading a single file.

How to Use it

Ask Questions About Your Codebase
/understand-chat How does the payment flow work?
This runs a natural language query against the knowledge graph. You get a structured answer grounded in the actual code. Not a hallucination, because the graph is built from your real files.
Try a few more:
/understand-chat Which services does the order module depend on?

/understand-chat What's the entry point for the user registration flow?
Explore Domain Logic
/understand-domain
This activates a 6th agent (domain-analyzer) that maps your code to business processes: domains, flows, and steps. Switch to the domain view in the dashboard.
Instead of seeing technical files, you see things like "Order Processing → Validate Cart → Reserve Inventory → Charge Payment". This is invaluable when you're trying to understand what the business logic actually does, not just how the code is structured.
Analyze Your Changes Before You Commit
You've made changes to a few files. Before you push:
/understand-diff
This shows you which parts of the graph your changes affect. You'll see downstream dependencies, potential ripple effects, and which other modules might need attention.
Deep-Dive a Specific File
/understand-explain src/auth/login.ts
Gets you a detailed breakdown of a single file or function — its purpose, what it calls, what calls it, and where it fits in the broader architecture.
Generate an Onboarding Guide
/understand-onboard
Auto-generates a guided walkthrough of the codebase for new team members. Useful for documentation or for sharing with someone joining the project.
Commit the Graph for Your Team
The graph is just a JSON file. Commit it once and your teammates skip the analysis pipeline on onboarding:
bash
git add .understand-anything/

git commit -m "Add knowledge graph"
Add these to .gitignore — they're local scratch and shouldn't be committed:
bash
.understand-anything/intermediate/

.understand-anything/diff-overlay.json
For large graphs (10 MB+), use git-lfs:
bash
git lfs install

git lfs track ".understand-anything/*.json"

git add .gitattributes .understand-anything/
Enable auto-updates so the graph stays fresh on every commit:
/understand --auto-update

What's Happening Under the Hood

The plugin isn't just calling an LLM and asking "explain this file." It's doing something more structured.
The file-analyzer agent extracts a formal graph representation: nodes for files, functions, and classes, with typed edges for imports, calls, and inheritance. This gives the dashboard something it can render — not just text to display.
The architecture-analyzer groups nodes into layers (API, Service, Data, UI, Utility) by analyzing the file structure and the nature of what each module exports and imports.
The tour-builder topologically sorts the graph — ordering the guided tour from foundational modules to high-level ones, so you learn the codebase in the right dependency order.
For the knowledge base use case (/understand-knowledge), there's a deterministic parser that extracts wikilinks and categories from index.md, combined with LLM agents that discover implicit relationships and extract claims. Two different approaches working together.
All file analyzers run in parallel (up to 5 concurrent, 20–30 files per batch). It supports incremental updates. Re-run /understand and it only re-analyzes files that changed since the last run.

Things to Keep in Mind While Using This Repo

  • LLM costs are on you. The multi-agent pipeline makes real LLM calls during the initial scan phase. Large repos with many files will accumulate non-trivial token costs. No published cost estimate exists for "average" codebase sizes.
  • Graph quality mirrors code quality. The tool surfaces structure that exists; it doesn't invent structure that doesn't. Poorly named functions, no separation of concerns, and large procedural scripts produce noisy graphs. No workaround. This is a fundamental property of the approach.
  • Initial scan time on large repos. First-run time scales with codebase size and LLM latency. Incremental updates are fast; the cold start is not. No benchmark for "time per KLOC" is published in the repo.
  • No published independent benchmark for graph accuracy. The DEV Community writeup confirms the tool is "actively maintained" and lists features, but no third-party has measured how often summaries are correct, how often architectural layer assignments are accurate, or how guided tours compare to human-written walkthroughs.
  • /understand-knowledge is under-documented. The Karpathy-pattern wiki analysis feature appears in the README and feature list but has no dedicated docs page, no example output, and no benchmark. The deterministic parser behavior (wikilink extraction) is described; the LLM-derived implicit relationship quality is not.
  • Cursor manual install fallback noted in README. Auto-discovery via .cursor-plugin/plugin.json doesn't always fire; the README now explicitly documents the manual fallback as of yesterday's commit.
  • No MCP server integration. Unlike GitNexus, Understand Anything does not expose the knowledge graph via MCP for agent consumption. The graph is human-facing and dashboard-based. Agents interact via /understand-chat and the plugin commands, not via a programmatic MCP interface.

FAQ

Does Understand Anything expose the knowledge graph via MCP for AI agents?
No. The graph is human-facing and accessed through the dashboard and plugin slash commands (/understand-chat, /understand-diff, etc.). It does not expose an MCP server for programmatic agent consumption. GitNexus does this instead.
What LLM does it use?
Whichever LLM is configured in your Claude Code (or other platform) session. The pipeline makes calls to your configured provider, costs depend on your model choice and codebase size. No default model is hardcoded in the plugin.
Is the graph stored locally or in the cloud?
The graph lives in .understand-anything/knowledge-graph.json in your repo, so entirely local. You can commit it to share with teammates. LLM API calls during indexing go to whatever provider you've configured; the graph output itself never leaves your machine.
How does incremental update work? Tree-sitter generates a fingerprint per file during the initial scan. On subsequent /understand runs, only files whose fingerprint has changed are re-analyzed. --auto-update automates this via a post-commit git hook.
Can it handle monorepos?
Yes, with subdirectory scoping: /understand src/frontend or /understand packages/api. Without scoping, very large monorepos will have long initial scan times and higher LLM costs.
What's the difference between the structural graph and the domain graph?
The structural graph (/understand) maps code: files, functions, classes, imports, layers. The domain graph (/understand-domain) maps business logic: domains, flows, and process steps. They're separate views of the same codebase. The domain view is more useful for PMs and business stakeholders; the structural view is more useful for engineers.
