00 - Introduction to Local LLMs
Most people use AI through a chat box.
You type a message > The model answers > It feels almost instant.
But under the surface, something much more interesting is happening. Your text gets broken into tokens. Those tokens move through a neural network. The model predicts what token should come next.
That prediction gets turned into text. Then the process repeats again, and again, and again.
That is the core loop behind modern language models.
And if you want to understand local LLMs, this is where you should start.
  • Not with leaderboards
  • Not with model drama
  • Not with “which model is best?”
  • Not with a giant list of tools
Start with the machine itself.
Takeaway: Local LLMs become much easier to understand once you learn how they generate one token at a time.

What is a local LLM?

A local LLM is a large language model that runs on hardware you control.
That could be:
  • your laptop
  • your desktop
  • a gaming PC
  • a MacBook
  • a Linux workstation
  • a home server
  • an AI Super computer
Instead of sending every prompt to a cloud API, the model runs locally.
The weights live on your machine. The runtime loads the model. Your hardware performs the inference. The output is generated where you are.
This is the big difference:
  • Cloud AI is something you access
  • Local AI is something you operate.
That does not mean local models are always better.
The strongest cloud models usually beat local models in raw capability. But local models give you something else:
  • privacy
  • control
  • offline access
  • experimentation
  • model choice
  • workflow ownership
  • lower marginal cost
  • deeper technical understanding
For many people, that is the point.
You are not just using an AI product.
You are learning how AI systems actually work.
Takeaway: A local LLM is not just a chatbot on your computer. It is a model, runtime, tokenizer, memory system, and inference loop running under your control.

The beginner mistake: starting too late

Most local LLM beginners start at the wrong layer.
They ask:
“What model should I download?”
“Should I use Ollama or LM Studio?”
“What does Q4 mean?”
“How much VRAM do I need?”
“Is this model better than that model?”
Those are good questions. But they are not the first questions.
Before you compare models, you need to understand what a model does.
Before you tune temperature, you need to understand generation.
Before you complain about context length, you need to understand tokens.
Before you chase bigger models, you need to understand weights and parameters.
Before you optimize speed, you need to understand inference.
This series starts at the foundation.
The goal is not to make you memorize every technical term.
The goal is to give you a mental model strong enough that the local LLM world stops feeling random.
Takeaway: If you understand the core mechanics first, tools and model choices become much easier later.

The simplest mental model

At the highest level, an LLM does one thing:
It predicts the next token.
That sounds too simple. But this simple loop powers almost everything you see:
  • chat responses
  • code generation
  • summarization
  • translation
  • reasoning traces
  • structured JSON output
  • tool calls
  • document Q&A
  • agent behavior
The model does not write a full answer all at once.
It generates one token, then another, then another.
A simplified version looks like this:
  1. You type a prompt.
  2. The tokenizer converts your text into tokens.
  3. The model reads the token sequence.
  4. The model calculates probabilities for the next token.
  5. A decoding method chooses the next token.
  6. That token gets added to the sequence.
  7. The process repeats until the answer is done.
This is the engine behind the magic.
When people say a model is “thinking,” “writing,” or “reasoning,” the actual process is still token prediction repeated many times.
That does not make it unimpressive. It makes it understandable.
Takeaway: LLMs generate text by repeatedly predicting the next token in a sequence.

Why “local” changes the learning experience

When you use a cloud chatbot, most of the system is hidden.
You usually do not see:
  • the model file
  • the tokenizer
  • the runtime
  • the context window
  • the inference settings
  • the sampling parameters
  • the KV cache
  • the memory limits
  • the hardware bottlenecks
You just see the final product.
Local LLMs expose more of the machine. That can feel confusing at first, but it is also the opportunity.
When you run models locally, you start seeing the real parts:
  • why token count matters
  • why long prompts slow things down
  • why small models answer differently
  • why quantized models fit on consumer hardware
  • why temperature changes creativity
  • why context is not the same as memory
  • why VRAM matters
  • why some models need specific chat templates
  • why a model file is more than “the AI”
This is why local LLMs are such a good learning path. They force you to understand the system.
Takeaway: Local LLMs make the hidden parts of AI visible, and that is what makes them so useful for learning.

You should be able to look at a local LLM and understand what is happening underneath the chat window.
Takeaway: This series teaches the mechanics behind local LLMs so you can use them with more confidence and less guesswork.

Final takeaway

A local LLM is not magic in a box.
It is a system.
  • Text becomes tokens.
  • Tokens become a sequence.
  • The model processes the sequence.
  • Weights shape the prediction.
  • Softmax turns scores into probabilities.
  • Sampling chooses the next token.
  • The answer grows one token at a time.
  • Transformer layers and attention make the whole process powerful.
Once you understand that loop, everything else gets easier.
  • Model formats.
  • Context windows.
  • Quantization.
  • Sampling settings.
  • KV cache.
  • Runtime choices.
  • Hardware limits.
  • Local workflows.
This is the foundation of Local LLM 101.
