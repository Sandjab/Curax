The problem

Long chain-of-thought reasoning produces sequences of 32,000 or more tokens. KV cache grows linearly with context length, filling VRAM before the model finishes.
SnapKV and R-KV address this by scoring key tokens using a narrow window of recent queries in post-RoPE space. Because RoPE rotates queries by position, that window is limited. Tokens not immediately relevant get permanently evicted before the model needs them.
In a depth-first search recursion benchmark, R-KV accuracy drops from 61% at depth 14 to 31% at depth 16. TriAttention tracks full attention up to that depth.

How TriAttention works

Standard KV compression relies on recent query signals to rank cached keys. TriAttention does not look at queries at all.
Pre-RoPE query and key vectors concentrate around fixed centers per attention head. Those centers encode each head's preference for nearby vs. distant tokens. Around 90% of Qwen3-8B attention heads have Mean Resultant Length R > 0.95, where R = 1.0 is perfect concentration. From those centers, TriAttention predicts a trigonometric score for each cached key based on position distance alone and prunes the lowest-scoring ones every 128 tokens.
Calibration is a one-time step per model. Pre-computed statistics ship for Qwen3-32B INT4. For other models,
calibrate.py
runs on any text corpus. The paper's ablation (Table F) shows Google homepage HTML achieves 46.2% on AIME24 vs. 46.7% for curated ShareGPT data. Calibration data quality does not meaningfully affect results.

How to get started

bash
git clone https://github.com/WeianMao/triattention.git
cd triattention
pip install -e .
pip install flash-attn --no-build-isolation
vLLM server:
bash
export TRIATTN_RUNTIME_KV_BUDGET=2048
export TRIATTN_RUNTIME_SPARSE_STATS_PATH=triattention/vllm/stats/qwen3_32b_int4_stats.pt

vllm serve <model_path> \
    --dtype bfloat16 \
    --max-model-len 32768 \
    --enforce-eager \
    --trust-remote-code \
    --enable-prefix-caching false
--enable-prefix-caching false is required. Prefix caching is currently incompatible with KV compression.
Python API:
python
from triattention.vllm.runtime.integration_monkeypatch import (
    install_vllm_integration_monkeypatches,
)
install_vllm_integration_monkeypatches(patch_scheduler=True, patch_worker=True)

from vllm import LLM, SamplingParams
llm = LLM(model="<model_path>", dtype="bfloat16", max_model_len=32768,
          enforce_eager=True, trust_remote_code=True)
Community ports for AMD via llama.cpp/HIP/ROCm (April 11) and Apple Silicon via MLX for M1-M4 (April 9) were released in the week after launch. The AMD port stacks with TurboQuant for ~6.8x effective KV reduction.

Limitations

No dedicated GPU kernel. Scoring runs through existing attention kernels, adding compute overhead. The paper identifies a FlashAttention-integrated kernel as the primary optimization target for future work.
Prefix caching incompatible. vLLM prefix caching must be disabled. Multi-turn chat deployments lose caching benefits until this is resolved.
Three verified model families. Qwen3-8B, DeepSeek-R1-Distill-Llama-8B, and DeepSeek-R1-Distill-Qwen-7B are confirmed. Other architectures require custom calibration without accuracy guarantees.
Benchmark on your own stack before treating this as production-ready.

Who this is for

Engineers running long-context inference on VRAM-constrained hardware, and teams serving reasoning models where throughput directly affects cost, should benchmark this now. The vLLM integration is transparent: two environment variables and no code changes.
Teams relying on vLLM prefix caching, anyone deploying outside the three verified model families, and retrieval-heavy workloads should wait. Retrieval benchmarks have not been published.

Practitioner implication

Engineers who were VRAM-blocked can now run 32B reasoning models on a single 24GB GPU, with TriAttention compressing KV cache 10.7x at runtime without accuracy loss.

AlphaSignal Take

TriAttention delivers what the README claims. The 10.7x compression and 2.5x throughput at matched AIME25 accuracy are reproducible from the paper's tables and the repo's own benchmark scripts.
Maintenance health is adequate for evaluation, not production. The repo is ten days old, three model families are verified, community ports are explicitly experimental, and no dedicated GPU kernel has shipped yet.
To earn a Production Ready verdict, TriAttention needs a FlashAttention-integrated scoring kernel, prefix caching compatibility, and validation across a wider set of architectures. Those items are on the roadmap but undelivered.
Worth Watching. Benchmark it on your stack today. Hold off on production commitment until kernel optimization and prefix caching land.

Questions?

Q: Does TriAttention work with any LLM? Currently verified on Qwen3-8B, DeepSeek-R1-Distill-Llama-8B, and DeepSeek-R1-Distill-Qwen-7B. Other models require running the included
calibrate.py
on a text corpus first. Accuracy retention on unverified architectures is not guaranteed.
Q: Do I need to run calibration before using it? Pre-computed statistics ship for Qwen3-32B INT4 in triattention/vllm/stats/. For other models, run
calibrate.py
on any text. The paper's ablation confirms calibration data quality has minimal effect: Google homepage HTML (46.2% AIME24) and curated ShareGPT data (46.7%) are within 0.5 percentage points.
Q: Will TriAttention affect accuracy on reasoning tasks? On AIME25 with a 3,072-token KV budget, TriAttention matches full attention exactly (40.8% vs. 40.8%) at 2.5x higher throughput. On MATH-500 with a 1,024-token budget, accuracy drops 1.2 percentage points (68.4% vs. 69.6%) while throughput increases 6.3x. Results on retrieval-heavy tasks have not been published.
