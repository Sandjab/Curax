07 - Transformers: The Core Engine
Previous Article -
06 - KV Cache and Session Memory
LLMs are not just magic text boxes.
Under the surface, modern language models are powered by a specific kind of neural network architecture: the transformer.
If tokens are the model’s input language, weights are what it learned, sampling is how it chooses outputs, and KV cache helps it move faster, then transformers are the engine that makes the whole system work.
In this article, we’ll build the big-picture mental model.
No heavy math. No matrix diagrams yet. Just the core idea you need before we go deeper into self-attention.

What you’ll learn

  • What a transformer actually does
  • Why LLMs process text as token sequences
  • How layers transform token representations
  • Why attention changed language modeling
  • Why transformers scale so well
  • Why they replaced older sequence models for many language tasks

The short version

A transformer is a model architecture designed to process sequences.
For LLMs, that sequence is tokens.
The model takes a list of token IDs, turns them into internal representations, passes those representations through many transformer layers, then produces scores for the next token.
That process repeats again and again during inference.
Simplified:
plaintext
Text
→ Tokens
→ Token representations
→ Transformer layers
→ Next-token scores
→ Sampling
→ Next token
→ Repeat
The transformer is not the whole local LLM system.
A local LLM also needs:
  • A tokenizer
  • Model weights
  • Config files
  • A chat template
  • An inference runtime
  • Sampling settings
  • Memory and compute
But the transformer architecture is the core model design that makes modern LLMs so capable.
Takeaway: A transformer is the engine that turns token sequences into next-token predictions.

LLMs work on sequences

Language is sequential.
The meaning of a word or token often depends on what came before it, what comes after it, and how it relates to other parts of the text.
Consider this sentence:
plaintext
The bank was closed because the river flooded.
The word “bank” does not mean a financial institution here. It means the edge of a river.
A useful language model needs to connect “bank” with “river flooded” to understand the likely meaning.
That is the central challenge:
A model needs to process tokens not as isolated chunks, but as parts of a larger sequence.
Older language systems struggled with this in different ways. Some could track nearby patterns well, but had trouble carrying useful information across longer text. Others processed sequences step by step, which made training harder to scale.
Transformers changed the default approach. They gave models a better way to process many token relationships across a sequence.
Takeaway: LLMs are sequence processors. The transformer is the architecture that lets them learn rich patterns across token sequences.

Tokens become representations

The model does not directly “read” words.
As we covered earlier in the series, text is converted into tokens. Those tokens become token IDs. The model then converts those IDs into internal numeric representations.
You can think of a token representation as the model’s current working description of that token.
Not just:
plaintext
Token: "bank"
But something closer to:
plaintext
This token appears in this position,
inside this sentence,
near these other tokens,
with these possible meanings,
under this current context.
At the start, the representation is basic.
After passing through transformer layers, it becomes more context-aware.
That matters because the same token can play different roles depending on the surrounding text.
For example:
plaintext
The bank approved the loan.
The bank overflowed after the storm.
Same token. Different context. Different meaning.
The transformer’s job is to keep refining each token’s representation based on the full sequence.
Takeaway: Transformers do not just store tokens. They repeatedly update token representations so each token becomes more context-aware.

Layers do the work

A transformer is built from layers.
Each layer takes in token representations and outputs improved token representations.
A small model may have fewer layers. A larger model may have many more. The exact number depends on the architecture.
The important idea:
Each layer gives the model another chance to refine what it knows about the sequence.
A rough mental model:
plaintext
Layer 1: basic token and position patterns
Layer 2: local phrase patterns
Layer 3: grammar and relationships
Layer 4+: richer concepts and longer-range structure
Later layers: increasingly abstract task-relevant patterns
That is an oversimplification, but it is useful.
The model is not doing one single giant calculation that instantly understands the prompt. It is repeatedly transforming the sequence through stacked layers.
Each layer asks, in effect:
plaintext
Given the current representation of every token,
how should each token representation change?
By the final layer, the model has built a much richer internal state.
That final state is used to predict the next token.
Takeaway: Transformer layers are repeated refinement steps. Each layer updates the model’s internal view of the token sequence.

Attention is the key idea

The breakthrough idea inside transformers is attention.
We will cover self-attention in more detail in article 08, but the high-level idea is simple:
Attention lets tokens influence each other.
Instead of processing each token in isolation, the model can learn which other tokens matter for understanding the current token.
Example:
plaintext
The trophy would not fit in the suitcase because it was too large.
What does “it” refer to?
Probably the trophy.
Now compare:
plaintext
The trophy would not fit in the suitcase because it was too small.
Now “it” probably refers to the suitcase.
A useful model needs to connect tokens across the sentence:
  • “it”
  • “trophy”
  • “suitcase”
  • “too large”
  • “too small”
Attention gives the model a mechanism for learning these relationships.
This is one reason transformers are so strong at language. They can model relationships between tokens, not just the order of tokens.
Takeaway: Attention lets the model decide which tokens should influence each other when building meaning.

Transformers are parallel-friendly

Before transformers became dominant, many sequence models processed text more strictly step by step.
That sounds natural because language is sequential.
But it creates a scaling problem.
If training requires processing one token after another in a long chain, it becomes harder to use modern hardware efficiently.
Transformers changed that.
During training, transformers can process many parts of a sequence in parallel. This made them much better suited to GPUs and large-scale training.
That does not mean generation is fully parallel.
During inference, an autoregressive LLM still generates one token at a time:
plaintext
Predict token 1
Append token 1
Predict token 2
Append token 2
Predict token 3
...
But the architecture itself is much more parallel-friendly during training than older approaches.
That helped unlock the scaling era. More data. More compute. Larger models. Better training runs.
Takeaway: Transformers became dominant partly because they match modern hardware well, especially during training.

Transformers scale unusually well

One of the biggest reasons transformers became the foundation for LLMs is that they scale.
When researchers trained larger transformer models on more data with more compute, the models often improved in surprisingly broad ways.
They got better at:
  • Translation
  • Summarization
  • Code generation
  • Question answering
  • Reasoning-like text patterns
  • Style transfer
  • Instruction following
  • Long-context pattern completion
Not perfectly. Not magically. Not always reliably.
But broadly enough that the architecture became the default engine behind modern language models.
This is one reason local LLMs exist in the form they do today.
The models you run through llama.cpp, Ollama, LM Studio, vLLM, or other runtimes are usually transformer-based models packaged for inference.
Different models may vary in architecture details, tokenizer, training data, context length, parameter count, and format. But the core engine is usually still a transformer.
Takeaway: Transformers became the default because they improved predictably as researchers scaled data, compute, and model size.

Why transformers replaced older approaches

Transformers did not win because they were simple.
They won because they were effective.
Compared with many older sequence modeling approaches, transformers had several advantages:
1. Better long-range relationships
They can connect tokens across a sequence more directly through attention.
2. Better scaling
They work well with large datasets, large models, and modern accelerator hardware.
3. Better parallel training
They avoid some bottlenecks of strictly step-by-step training.
4. Flexible pattern learning
They can learn grammar, facts, style, code structure, reasoning traces, formatting conventions, and task patterns from large text datasets.
5. Reusable architecture
The same general architecture can support many text tasks without needing a separate hand-built system for each one.
They have real limits:
  • Context windows are finite
  • Inference can be expensive
  • Long prompts cost memory and compute
  • They can hallucinate
  • They do not have true built-in long-term memory
  • They predict tokens, not guaranteed truth
But they are powerful enough that most modern LLMs are built around them.
Takeaway: Transformers replaced many older language architectures because they handle token relationships well and scale extremely effectively.

The local LLM angle

When you run a local LLM, the transformer is what your machine is actually executing.
Your runtime loads the model weights into memory. The tokenizer converts your prompt into tokens. The transformer processes those tokens through its layers. The model produces scores for the next token. Sampling picks the next token. The runtime appends it to the sequence and continues.
That is why local performance depends on things like:
  • Model size
  • Number of layers
  • Context length
  • KV cache size
  • Quantization
  • CPU, GPU, or NPU speed
  • Memory bandwidth
  • Runtime optimization
A 7B model is not just “a file.” It is a transformer network with billions of learned parameters that must be loaded, processed, cached, and sampled from.
This is why local inference feels mechanical once you understand the stack.
Your machine is not summoning answers.
It is repeatedly running a transformer forward pass over token representations.
Takeaway: Running a local LLM means running a transformer efficiently on hardware you control.

Save-worthy framework: the transformer stack

Here is the simple framework to remember:
plaintext
1. Tokens
Text becomes token IDs.

2. Representations
Token IDs become internal vectors.

3. Layers
The model repeatedly transforms those representations.

4. Attention
Tokens influence each other based on context.

5. Prediction
The final representation helps score the next token.

6. Sampling
The runtime chooses the next token.

7. Repeat
The new token is added, and the loop continues.
Or even shorter:
plaintext
Tokens in.
Representations refined.
Next token out.
Repeat.
That is the transformer-powered LLM loop.
Takeaway: A transformer is best understood as a layered sequence engine that refines token representations until the model can predict what should come next.

Common beginner mistakes

Mistake 1: Thinking the model reads words like humans do
It does not. It processes token IDs and internal numeric representations.
Words are only part of the story. Tokenization, position, and surrounding context all matter.
Takeaway: The model works with token sequences, not human-readable words directly.
Mistake 2: Thinking one layer “understands” the prompt
Understanding-like behavior emerges from many stacked transformations. Each layer refines the sequence. No single layer is the whole model.
Takeaway: Transformer capability comes from repeated refinement across many layers.
Mistake 3: Thinking attention is memory
Attention is not long-term memory.
Attention helps tokens in the active context influence each other. It does not permanently store new facts in the model’s weights.
If something is not in the model weights, not in the active context, and not retrieved from an external system, the model cannot reliably use it.
Takeaway: Attention connects tokens in context. It is not the same as memory.
Mistake 4: Thinking bigger always means better
Larger transformer models often have more capacity, but size alone does not guarantee better results.
Quality also depends on:
  • Training data
  • Architecture choices
  • Fine-tuning
  • Tokenizer
  • Context length
  • Quantization
  • Runtime settings
  • The task itself
A smaller model can beat a larger model for a specific use case if it is better trained or better matched to the task.
Takeaway: Parameter count matters, but it is not the only thing that matters.
Mistake 5: Thinking transformers guarantee truth
A transformer predicts likely next tokens based on learned patterns and context.
That can produce useful answers. It can also produce confident wrong answers.
The architecture is powerful, but it is not a truth engine by default.
Takeaway: Transformers are prediction engines. Reliability still requires grounding, verification, and good workflows.

Practical next step

Open the model card for a local model you use.
Look for architecture details such as:
  • Model family
  • Parameter count
  • Number of layers
  • Context length
  • Tokenizer type
  • Training or fine-tuning notes
  • Supported chat template
  • Quantized formats, if available
You do not need to understand every field yet. Just start seeing the model as a structured system, not a mysterious download.
Takeaway: A model card is easier to read once you know the transformer is the core engine underneath.

Final takeaway

Transformers are the core engine behind modern LLMs.
They process token sequences, refine token representations through layers, let tokens influence each other through attention, and produce the next-token scores that sampling turns into text.
Once you understand this, local LLMs stop feeling like magic.
They become a stack:
plaintext
Tokenizer
+ Transformer
+ Weights
+ Context
+ Sampling
+ Runtime
+ Hardware
