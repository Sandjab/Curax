05 - Generation, Softmax, Greedy, and Sampling
Previous Article -
04 - What a Model Actually Includes
A LLM does not write an answer.
A local LLM generates text one token at a time by repeatedly asking:
“Given everything so far, what token should come next?”
The interesting part is not just the prediction.
The interesting part is how the model chooses from many possible next tokens.
That choice is where softmax, greedy decoding, temperature, top-k, and top-p sampling come in.
If you have ever wondered why the same prompt can produce different answers, this is the article that explains it.

What you’ll learn

By the end, you’ll understand:
  • What logits are
  • How softmax turns raw scores into probabilities
  • Why greedy decoding is deterministic
  • Why sampling can make outputs more creative
  • How temperature, top-k, and top-p shape generation
  • Why generation settings matter when running local LLMs

The model does not directly output words

When you send a prompt to an LLM, the model does not directly say:
“The next word is definitely cat.”
Instead, it produces a score for every possible next token in its vocabulary.
These raw scores are called logits.
A tokenizer might have tens of thousands or hundreds of thousands of possible tokens. For the next position, the model assigns each one a score.
Example:
  • cat: 8.2
  • dog: 7.9
  • animal: 6.4
  • car: 1.1
  • banana: -0.3
These are not probabilities yet. They are raw model preferences.
Higher score means the model currently thinks that token is more likely to come next.
Takeaway: The model first produces raw scores for possible next tokens, not final text.

Softmax turns scores into probabilities

The next step is to convert those raw scores into a probability distribution.
That is what softmax does.
Softmax takes the model’s logits and turns them into probabilities that add up to 100%.
Example:
  • cat: 48%
  • dog: 36%
  • animal: 12%
  • car: 3%
  • banana: 1%
Now the runtime has something it can choose from.
This matters because generation is not just about what the model “knows.”
It is also about how the runtime selects the next token from the probability distribution.
The model gives possibilities. The decoding strategy chooses one.
Takeaway: Softmax converts raw model scores into probabilities, creating the menu of likely next tokens.

Greedy decoding picks the top token

The simplest decoding strategy is greedy decoding.
Greedy decoding always picks the token with the highest probability.
If the model says:
  • cat: 48%
  • dog: 36%
  • animal: 12%
  • car: 3%
  • banana: 1%
Greedy decoding picks:
cat
Every time.
If you run the exact same prompt with the exact same model and deterministic settings, greedy decoding should produce the same output.
That can be useful.
Greedy decoding is good when you want stable, repeatable answers. It can be useful for extraction, formatting, simple classification, or tasks where creativity is not the goal.
But it has a weakness. Language is often not a single correct path.
At every token, there may be several reasonable choices. If the model always picks the most likely one, the output can become bland, repetitive, or overly obvious.
Takeaway: Greedy decoding is predictable because it always chooses the highest-probability next token.

Sampling chooses from likely tokens

Sampling is different.
Instead of always picking the most likely token, sampling treats the probability distribution like a weighted lottery.
If the model says:
  • cat: 48%
  • dog: 36%
  • animal: 12%
  • car: 3%
  • banana: 1%
Sampling usually picks cat or dog, but it might sometimes pick animal.
It probably will not pick banana, unless your settings make the distribution very loose.
This is why the same prompt can produce different answers.
The model may produce a similar probability distribution each time, but the sampling step can choose different valid paths.
Once a different token is chosen, the rest of the generation changes too, because the new token gets appended to the context.
That changes the next prediction.
Then the next one.
Then the next one.
A small difference early in generation can lead to a noticeably different answer later.
Takeaway: Sampling introduces controlled randomness by choosing from likely next tokens instead of always taking the top one.

Temperature controls sharpness

Temperature changes how sharp or flat the probability distribution is before sampling.
Lower temperature makes the model more confident.
Higher temperature spreads probability across more options.
Imagine this distribution:
  • cat: 48%
  • dog: 36%
  • animal: 12%
  • car: 3%
  • banana: 1%
With a lower temperature, it might become more like:
  • cat: 70%
  • dog: 24%
  • animal: 5%
  • car: 1%
  • banana: almost 0%
The top options dominate.
With a higher temperature, it might become more like:
  • cat: 35%
  • dog: 30%
  • animal: 20%
  • car: 10%
  • banana: 5%
More tokens have a real chance. That can make outputs more varied, surprising, and creative.
It can also make them less reliable.
A useful mental model:
  • Low temperature: more focused, predictable, conservative
  • Medium temperature: balanced, natural, flexible
  • High temperature: more random, creative, risky
For many local LLM use cases, temperature is one of the most important knobs.
  • If your model sounds boring, temperature may be too low.
  • If your model rambles or invents too much, temperature may be too high.
Takeaway: Temperature controls how strongly the model favors the most likely tokens versus exploring less likely ones.

Top-k limits the candidate pool

Top-k sampling limits the model to only the k most likely next tokens.
If k = 40, the runtime only considers the top 40 tokens.
Everything below that is ignored.
This prevents the model from choosing very unlikely tokens, even if temperature would otherwise give them a tiny chance.
Example:
The model has 128,000 possible tokens.
Top-k says:
“Only sample from the top 40.”
That keeps generation from drifting into weird low-probability choices.
A smaller k makes output more constrained. A larger k gives the model more room.
Common intuition:
  • top-k = 1: basically greedy decoding
  • small top-k: focused and conservative
  • larger top-k: more diverse
  • no top-k limit: the full vocabulary may remain available, depending on other settings
Top-k is simple and easy to understand, but it does not adapt to the shape of the probability distribution.
Sometimes the model is very confident and only a few tokens matter.
Other times many tokens are plausible. Top-k always cuts at the same number.
Takeaway: Top-k sampling keeps only the top k candidate tokens, blocking very unlikely choices from being selected.

Top-p adapts to confidence

Top-p sampling, also called nucleus sampling, works differently.
Instead of keeping a fixed number of tokens, top-p keeps the smallest set of tokens whose combined probability reaches a threshold.
If top-p = 0.9, the runtime keeps enough tokens to cover 90% of the probability mass.
Example:
  • cat: 48%
  • dog: 36%
  • animal: 12%
  • car: 3%
  • banana: 1%
To reach 90%, the runtime might keep:
  • cat: 48%
  • dog: 36%
  • animal: 12%
Total: 96%
Then it samples only from those tokens.
The key difference: Top-p adapts.
If the model is very confident, top-p may keep only a few tokens.
If the model is uncertain, top-p may keep many.
That makes it more flexible than top-k in many generation scenarios.
Common intuition:
  • lower top-p: more focused
  • higher top-p: more diverse
  • top-p = 1.0: less filtering by nucleus sampling
Top-p is popular because language uncertainty changes from token to token.
Sometimes the next token is obvious. Sometimes many choices are reasonable.
Top-p responds to that.
Takeaway: Top-p keeps enough likely tokens to reach a cumulative probability threshold, making it more adaptive than top-k.

Why the same prompt can produce different answers

Now the full loop looks like this:
  1. Your prompt becomes tokens.
  2. The model processes the sequence.
  3. The model produces logits for the next token.
  4. Softmax turns logits into probabilities.
  5. Decoding settings filter or reshape the distribution.
  6. The runtime chooses one token.
  7. That token is appended to the sequence.
  8. The process repeats.
If you use greedy decoding, step 6 always picks the top token.
If you use sampling, step 6 can choose different likely tokens across runs.
That is why local LLM generation can feel inconsistent.
It is not necessarily a bug. It is often a decoding choice.
The same model can behave like:
  • a deterministic autocomplete engine
  • a careful assistant
  • a brainstorming partner
  • a chaotic fiction generator
The difference may come from only a few generation settings.
Takeaway: Output variability comes from the token selection step, not from the model generating an entire answer all at once.

Determinism versus creativity

There is no single best setting. There are tradeoffs.
If you want precise, repeatable behavior, use more deterministic settings.
Good for:
  • data extraction
  • structured output
  • classification
  • code edits
  • factual Q&A
  • evals and benchmarks
If you want variety, use sampling.
Good for:
  • brainstorming
  • writing
  • roleplay
  • creative ideation
  • alternative phrasings
  • exploration
A practical starting point:
  • For factual or structured tasks: lower temperature, tighter top-p
  • For creative tasks: moderate temperature, wider top-p
  • For maximum repeatability: greedy or near-greedy settings
  • For experimentation: change one setting at a time
The mistake is treating generation settings as decorations.
They are not. They are part of the behavior of the system.
Takeaway: Generation settings are behavioral controls. They shape whether the same model acts precise, flexible, creative, or chaotic.

A simple decoding framework

Here is the save-worthy mental model:
Every generated token goes through this sequence:
1. Scores
  • The model outputs logits for possible next tokens.
2. Probabilities
  • Softmax turns those logits into probabilities.
3. Filtering
  • Temperature, top-k, top-p, and related settings reshape or limit the choices.
4. Choice
  • Greedy decoding picks the top token.
  • Sampling picks from the remaining distribution.
5. Repeat
  • The chosen token is appended, and the model predicts again.
This is why generation is both mechanical and flexible.
The model is not writing a paragraph in one shot. It is making thousands of tiny next-token decisions.
Takeaway: Text generation is an iterative loop of scoring, filtering, choosing, and repeating.

Common beginner mistakes

Mistake 1: Thinking temperature means intelligence
Temperature does not make a model smarter. It changes how boldly the runtime samples from the model’s probabilities.
A high temperature can produce more surprising answers, but it can also produce worse ones.
Takeaway: Temperature controls randomness, not capability.
Mistake 2: Using creative settings for factual tasks
If you ask a model for exact information while using very loose sampling, you increase the chance of drift. For factual tasks, you usually want the model to stay close to its strongest predictions.
Takeaway: Match decoding settings to the job.
Mistake 3: Assuming greedy is always best
Greedy decoding is stable, but it can be rigid.
For open-ended writing, brainstorming, or explanation, sampling may produce more natural results.
Takeaway: Deterministic does not always mean better.
Mistake 4: Changing too many knobs at once
If you change temperature, top-p, top-k, repeat penalties, context length, prompt format, and model version all at once, you will not know what caused the difference.
Change one variable at a time.
Takeaway: Treat generation settings like an experiment, not a magic spell.
Mistake 5: Forgetting that each token changes the next prediction
One different token early in the answer can shift the entire continuation.
That is why two generations can start similarly and end differently.
Takeaway: Generation is path-dependent. Every chosen token affects what comes next.

Practical next step

Pick one local model and one prompt.
Run the same prompt three times with different settings:
1. Greedy or near-greedy
  • Very low temperature
  • Tight sampling
2. Balanced
  • Medium temperature
  • Moderate top-p
3. Creative
  • Higher temperature
  • Wider top-p
Then compare:
  • Does the answer repeat?
  • Does it become more varied?
  • Does it become less factual?
  • Does it become more interesting?
  • Where does quality peak for your use case?
Do not just ask, “Which setting is best?”
Ask:
“Best for what?”
That is the real question.
Takeaway: The right generation settings depend on whether you want precision, consistency, variety, or creativity.

The Core Lesson

A local LLM does not simply “decide” an answer.
It scores possible next tokens.
Softmax converts those scores into probabilities. Decoding settings reshape the choices.
Then the runtime picks one token and repeats the process.
That means model behavior is partly learned from training and partly shaped at inference time.
The weights define what the model tends to predict.
The decoding settings define how strictly or creatively you follow those predictions.
Once you understand that split, local LLMs become much less mysterious.
You are not just running a model.
You are steering a generation process.
