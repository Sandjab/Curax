Part I: What MCP Actually is

MCP stands for Model Context Protocol. You'll forget the name. Here's what it does:
It lets AI models connect to external services through servers. Each server gives Claude new tools. Install a GitHub server: Claude reads your PRs. Install Postgres: Claude talks to your database. Install Playwright: Claude opens a real browser on your screen.
Think of it like mods for a game. Each MCP server snaps in a new capability that wasn't there before.
The part most tutorials skip: MCP is not a Claude thing. Anthropic built it, then donated it to the Linux Foundation. OpenAI, Google, Microsoft, AWS, GitHub all adopted it. Nobody owns it. One server works with Claude Code, Cursor, VS Code, Windsurf, Claude Desktop. Install once, use everywhere.
That's why the ecosystem is growing this fast. SkillsIndex went from 425 to over 4,000 servers in under a year.

Part II: Your First Server in 10 Seconds

Enough theory.
Context7 is an MCP server by Upstash that gives Claude access to current documentation for frameworks and libraries. This matters more than you think, because Claude (like every AI model) was trained on data that's already outdated. It will confidently use deprecated APIs without telling you.
I've had Claude generate an entire component with a React pattern that was removed two versions ago. Spent an hour debugging before I realized the code was technically correct for React 17. I was on React 19.
Context7 fixes that. Claude checks live docs before writing code.
Install it. Open your terminal:
bash
claude mcp add context7 -- npx -y @upstash/context7-mcp
That's it. One command. Done. Let me break it down:
If you prefer a remote connection instead of running it locally:
bash
claude mcp add --transport http context7 https://mcp.context7.com/mcp
Remote is simpler. Local works offline. Either way, start Claude Code and type /mcp You should see a green checkmark next to context7
Now try this prompt:
"Check the latest Tailwind docs to see if the theme variables are correctly configured in my global CSS file. Use context7."
Claude will resolve the library, pull the current docs, and check your code against the actual spec. Not against whatever it learned during training.
Here's the move that made the biggest difference for me: add a memory so Claude does this automatically every time.

Part III: Claude Gets Eyes

Context7 gives Claude knowledge. Playwright gives Claude vision.
Playwright MCP is Microsoft's official package (playwright/mcp) Claude opens a real browser on your machine, navigates pages, clicks elements, fills forms, reads the accessibility tree.
Quick heads up: if you google "Playwright MCP" you'll find two packages. > executeautomation/playwright-mcp-server is a community project. > playwright/mcp is the official Microsoft one. I'm using the official one. Don't mix them up.
bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
Restart Claude Code. /mcp Green checkmark. You're live.
Try this:
Claude opens Chrome. Loads your page. Reads the structure through the accessibility tree and gives you real UX feedback.
Small gotcha that Simon Willison flagged: say "playwright mcp" explicitly the first time you use it. Otherwise Claude might try to run Playwright through bash instead of the MCP server. After the first time it gets it.
What I actually use this for:
> Visual QA after building a component. Claude opens the page and tells me if the spacing is off or if something doesn't look right.
> End-to-end testing in plain English. "Go to the signup page, fill in test data, submit, check if the success message appears." No test scripts.
> Authenticated sessions. Claude opens the login page, I type my password manually, cookies persist. Then Claude can navigate the authenticated app.
Remember the problem from the intro? Claude was locked in a room. Context7 gave it a library card. Playwright gave it a window.
Two terminal commands. Already a completely different tool.

Part IV: Scopes and the Config File

Every MCP server you add has a scope. Three options:
I use --scope project for anything team-specific (database, project management tools) --scope user for things I always want like Context7 and Brave Search. I almost never use --scope local Tbh I forget it exists.
When you add a server, Claude Code creates a config file. For project scope that's .mcp.json in your project root:
json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp"
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
stdio = server runs locally on your machine. http = remote connection. Simpler setup but depends on someone else's infrastructure.
Windows users: the setup is still clunky. Not gonna sugarcoat it. If you're on native Windows (not WSL) you need the cmd /c wrapper for npx servers:
bash
claude mcp add --transport stdio my-server -- cmd /c npx -y @some/package
Without it you'll get "Connection closed" errors. In the JSON config:
json
{
  "command": "cmd",
  "args": ["/c", "npx", "-y", "@upstash/context7-mcp"]
}
On Mac and Linux everything just works. I'm hoping the Windows situation improves. Maybe by the time you read this it already has.

Part V: The Servers That Changed How I Work

There are thousands of servers. You need maybe 5-8. Here are the ones I'd actually recommend:
> GitHub MCP. Claude reads issues, reviews PRs, searches code across repos, creates branches. No more switching between terminal and GitHub every 30 seconds.
bash
claude mcp add github --scope user -- \
  docker run -i --rm \
  -e GITHUB_PERSONAL_ACCESS_TOKEN=ghp_your_token \
  ghcr.io/github/github-mcp-server
Uses GitHub official Docker image. Set your personal access token and you're in.
> PostgreSQL / Supabase. Claude queries your database directly.
bash
claude mcp add postgres --scope local -- \
  npx -y @bytebase/dbhub \
  --dsn "postgresql://user:pass@localhost:5432/mydb"
I shouldn't have to say this but: read-only access only. Never point this at prod with write permissions.
> Brave Search. Claude can't access the internet by default. Brave Search gives it web search. Current docs, recent articles, security advisories.
bash
claude mcp add brave-search --scope user -- \
  npx -y @brave/brave-search-mcp-server
Free tier: 2,000 queries/month. Set BRAVE_API_KEY in your environment.
> Context7 Already covered above. Live docs for any framework.
> Playwright Already covered. Browser automation and visual QA.
> Slack MCP Claude reads channels, searches conversations, posts updates. I use it to pull context from team discussions without opening Slack.
> Memory MCP Persistent memory across sessions. "Remember this architecture decision" today. "What did we decide about the auth service?" three weeks later. It actually remembers.
> Sequential Thinking Forces Claude into structured reasoning on hard problems. Reduces the failure mode where Claude sounds confident but is completely wrong.
Start with Context7 + Playwright. Add GitHub and your database next. Then expand based on what you actually use every day.
Don't install 10 servers on day one. Add what you need when you need it.

Part VII: Why 10+ Servers Don't Break Anything

If you're wondering: what happens when I connect 10 MCP servers? Doesn't that flood Claude context with tool definitions?
No. Claude Code has something called Tool Search that most other clients don't have.
Instead of loading every tool from every server into context at once, Claude Code discovers tools on demand. It only pulls in the schema for tools it actually needs for the current task.
This cuts context usage by up to 95% compared to clients that dump all tool definitions upfront.
You can connect 15, 20 servers. Claude ignores the ones it doesn't need. It lazy-loads what's relevant and moves on.
This is why Claude Code is the strongest MCP client right now! Cursor and Claude Desktop load everything at startup. Claude Code is selective. The more servers you add, the more this matters.
