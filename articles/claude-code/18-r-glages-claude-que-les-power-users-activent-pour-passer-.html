Most people think Claude is “getting worse.”
Usually?
Their setup is.
Anthropic shipped 100+ settings, toggles, hooks, memory systems, MCP controls, cache layers, reasoning modes, and workspace configs across
Claude.ai
, Claude Code, and the API stack.
Most users never touch them.
So their:
  • token bills creep up
  • outputs drift
  • context gets polluted
  • sessions slow down
  • autonomous runs break
  • memory becomes garbage
  • plugins silently eat context
  • MCP servers bloat prompts
  • hooks misfire
  • projects lose consistency
Then they blame the model.
The people getting insane results from Claude right now are not “better prompters.”
They’re better operators.
Here are the settings and workflows that actually change performance.
—

1. Memory Scope (Most Important
Claude.ai
Setting)

Where: Settings → Capabilities → Memory
Most users leave memory global.
That’s a mistake.
After a month Claude starts mixing:
  • random preferences
  • old projects
  • stale corrections
  • unrelated context
  • temporary instructions
into every conversation.
Output quality slowly drifts.
The fix:
Turn on project-scoped memory.
Now each project keeps its own context silo.
Also use:
“forget what you remembered about X”
inside chats.
Way faster than manually cleaning memory.
—

2. Extended Thinking

Where: Model selector → Extended Thinking
Three modes:
  • Off
  • Light
  • Full
Most people run Full everywhere because “more reasoning = better.”
Wrong.
For:
  • summarization
  • rewriting
  • formatting
  • translation
  • quick edits
it mostly adds:
  • latency
  • token burn
  • slower UX
without improving answers.
Best setup:
  • Light by default
  • Full only for debugging, architecture, math, planning
This alone cuts serious Opus waste.
—

3. Custom Styles Are Secretly System Prompts

Most users think Styles are:
“formal” “concise” “friendly”
No.
Custom Styles are reusable output contracts.
You can permanently enforce:
  • formatting
  • banned words
  • sentence length
  • response structure
  • citation rules
  • code formatting
  • writing tone
  • thread structure
across every response.
My X writing style blocks:
  • “delve”
  • “robust”
  • “game-changing”
  • em dashes
  • generic hooks
and forces:
  • short sentences
  • curiosity gaps
  • concrete numbers
  • punchy endings
One style replaces 50 prompts.
—

4. Project Instructions

Most people upload files into Projects…
…and leave instructions empty.
That field is basically a persistent system prompt.
Every chat inherits it.
Meaning:
you stop re-explaining your workflow forever.
Good Project Instructions include:
  • role
  • skepticism level
  • formatting rules
  • things Claude should NEVER do
  • decision frameworks
  • tone constraints
  • preferred output structure
Treat it like CLAUDE.md for your brain.
—

5. Search Past Chats

Hidden thing nobody realizes:
Claude chat search is mostly keyword-based.
Not semantic.
“This thing we discussed last week” fails.
“Polymarket Iran probabilities” works.
The unlock:
use dense nouns when naming chats.
Your future self will thank you.
—

6. Web Search Citation Mode

Default inline citations are horrible for copy-paste.
Switch to:
Footnotes mode.
Now Claude outputs clean text + sources separately.
Way better for:
  • docs
  • emails
  • posts
  • research exports
Tiny setting. Massive quality-of-life improvement.
—

7. Trusted Folders (Cowork)

This one is dangerous.
Claude remembers trusted folders.
Meaning folders you approved months ago may STILL be accessible.
Audit them regularly.
People forget test directories, client folders, or old repos remain trusted forever.
—

8. Incognito Chats

Incognito does more than hide chats.
It disables:
  • memory writes
  • history indexing
  • searchability
  • training usage
  • persistent storage
Use it for:
  • contracts
  • client names
  • salary discussions
  • legal drafts
  • medical info
Most users never touch it.
—

9. enabledPlugins (Claude Code)

Installed ≠ active.
Every enabled plugin loads:
  • schemas
  • hooks
  • skills
  • instructions
into context.
Forgotten plugins silently burn tokens every session.
Power users aggressively disable unused ones instead of uninstalling.
Huge context savings.
—

10. permissions.deny

Critical for Claude Code.
Block access to:
  • .env
  • secrets
  • sudo
  • dangerous shell commands
But there’s a catch:
the deny system has edge-case failures.
So serious users add OS-level protection too.
Never rely on Claude-side protection alone.
—

11. SessionStart Hooks

This is where things get interesting.
Hooks let Claude auto-load context when sessions begin.
Advanced users dynamically inject:
  • branch-specific context
  • current project state
  • TODOs
  • architecture rules
  • workflow constraints
instead of stuffing everything into gigantic CLAUDE.md files.
Result:
smaller context, better focus, less drift.
—

12. disableAllHooks

The emergency kill switch.
If Claude starts:
  • acting weird
  • freezing
  • running phantom commands
  • looping
…it’s often a broken hook.
disableAllHooks instantly isolates the problem.
Underrated debugging tool.
—

13. Per-Project Model Overrides

Most people globally run Opus.
Expensive mistake.
Your docs project doesn’t need Opus.
Your shell scripts probably don’t either.
Power users map models to workload:
  • Haiku → docs + markdown
  • Sonnet → infra + coding
  • Opus → hard architecture
Massive cost optimization.
—

14. MCP Servers

Biggest hidden token leak in Claude Code.
Every connected MCP server injects tool schemas into context.
People connect:
  • Slack
  • Jira
  • Postgres
  • GitHub
  • Linear
  • browser MCPs
…and forget about them.
6 months later: 40K+ tokens gone before work even starts.
The fix:
keep servers installed, but disabled by default.
Enable per session.
—

15. cleanupPeriodDays

Nobody talks about this.
Claude Code stores:
  • transcripts
  • logs
  • session artifacts
  • historical context
Longer retention massively improves long-horizon workflows.
Especially for:
  • Dreaming
  • memory consolidation
  • historical debugging
  • agent continuity
180 days > 30 days.
Disk cost is tiny.
—

16. cache_control (Most Important API Setting)

This single API optimization can cut bills by 70%+.
Most people cache the WRONG part of prompts.
The rule:
cache stable prefixes.
Meaning:
  • system prompts
  • instructions
  • static context
  • schemas
NOT user messages.
One breakpoint placement mistake can literally triple API cost.
—

17. inference_geo

Hidden billing multiplier.
Region-locked inference can add pricing overhead.
A lot of teams enable residency “just to be safe” without actually needing it.
Result:
higher bills forever.
Check compliance before enabling region locks.
—

18. Workspace Rate Limits

The setting that saves startups at 3am.
Without workspace isolation:
one runaway batch job can nuke your entire quota.
Then production chat dies.
Serious teams isolate:
  • customer chat
  • batch processing
  • experiments
  • internal tooling
into separate workspaces with separate caps.
That’s how you stop one bug from taking down everything.
