10 hours of Claude Code course → the techniques that actually matter

Nate Herk dropped a 10-hour course on Claude Code on March 12. 597,000 views in two months. I watched all of it across three days so you don't have to. Here is what is worth your time and what to skip.

The course is free, on YouTube under "Build & Sell with Claude Code". The thumbnail looks like every other AI bro thumbnail. The runtime is 9 hours 58 minutes. The premise sounds insane: build production AI workflows, deploy websites, build agent teams, find clients, price your work, without writing a single line of code.
I clicked because I keep seeing Claude Code mentioned everywhere and I had not used it seriously. Three days later I have a Notion doc with 47 bullet points and I am writing this.
Upfront verdict. About 30% of the runtime is repeat content from Nate's earlier videos. Another 15% is plug for his paid Skool group. The remaining 55% is the most concentrated practical tutorial on Claude Code that exists in 2026, and the business section nobody else teaches at this level.
What you actually need to know is below.

Who Nate is and why this matters

Nate Herkelman, 23, Chicago. Goldman Sachs BI Analyst. Quit November 2024 to build AI automation full time.
By March 2026 his YouTube is at 595K subscribers, his free Skool community at 305,600 members. Verified n8n Expert Partner. Won the Skool Games Tech category four quarters in a row in 2025.
His documented client work, from a public PDF, is four AI agents sold in 2025 for $23,000 total. The breakdown is later in this article.
Most "make money with AI" content is from people who have never sold anything. Nate has receipts, even if smaller than his marketing headlines imply. The course is him compressing what he learned doing this into 10 hours.

The big idea: Claude Code is no longer just for coding

This framing runs through the whole course and it took me an hour to fully accept it.
Most people think Claude Code is a CLI tool for developers writing software. Nate's argument: as of 2026, it is the most flexible agent runtime that exists. You can use it to build n8n workflows, deploy websites, run a personal executive assistant, automate browser tasks, orchestrate teams of subagents. The fact that you do this through a terminal does not mean you need to code.
Mental shift: Claude Code is not an IDE. It is an agent that lives in your terminal and can read, write, run files on your machine. Once that clicks, the rest of the course makes sense.

I. Setup and operations (00:00 to 50:53)

The first hour is genuinely useful even if you have Claude Code installed. A few things I did not know:
The CLAUDE.md file matters more than people realize. This is the file Claude reads at the start of every session in a project folder. Treat it like a system prompt for your project. Include: what the project does, what tech stack you use, file conventions, where things live, what NOT to do. Without it, every session starts from zero.
Tokens and context windows actually matter. Claude Code shows you a context bar at the bottom. Once it fills, the model forgets. Nate's rule: clear the context manually (/clear) whenever you finish a discrete task. Long sessions degrade. Short focused sessions with cleared context win every time.
Slash commands you will actually use:
/init       generates a starter CLAUDE.md from your repo
/clear      wipes context, fresh start, keeps the project
/agents     manage subagents
/mcp        list connected MCP servers
/plugin     install plugins and skills
/chrome     connect to the Chrome extension
If you only remember three, remember /init, /clear, and /agents. Those three carry 80% of the course.

II. First and second workflows (58:57 to 1:50:43)

Nate builds two workflows live. Both are n8n because n8n is his bread and butter. The technique is what matters.
His framework is WAT: What, Automate, Test. Before you touch Claude Code, write down in plain English what the workflow needs to do, which specific steps to automate, and how you will test it.
Paste this into Claude Code as a single prompt. Nate's actual phrasing: "I want you to build a workflow that does X. Before you do anything, ask me three clarifying questions." That last sentence about clarifying questions is what changed it for me. Forcing Claude Code to ask before doing prevents most wrong-direction problems I had been hitting.
The two workflows are a content repurposing agent (YouTube transcript to LinkedIn + X thread + newsletter) and a lead enrichment agent (CSV of companies to personalized outreach). Neither is novel. The value is watching him talk to Claude Code in real time. Half the time it produces something wrong on the first try and he walks through how he fixes it. Honestly the fixing part is what I learned from, not the workflows themselves.

III. Deploying automations (1:50:43 to 3:05:46)

The longest section, 75 minutes on deployment.
Setup: write workflows locally with Claude Code, push to a VPS, run on cron. Nate uses Hostinger. Any VPS works.
The useful bit is the self-healing workflow pattern. n8n workflows break for predictable reasons: API token expired, schema changed, rate limit hit. Nate wires up an error-handling workflow that fires when any other workflow fails. The error workflow calls Claude Code as a subprocess on the VPS, passes the broken workflow JSON and the error, Claude rewrites the workflow to fix it.
Clever. Whether you trust production workflows to self-rewrite is another question. For personal automations, this pattern works.

IV. Project architecture and commands (3:05:46 to 3:17:39)

Short section but important.
project-folder/
├── CLAUDE.md              system prompt for the project
├── .claude/
│   ├── agents/            custom subagents
│   ├── skills/            project-specific skills
│   └── commands/          custom slash commands
└── your actual files
Custom slash commands are markdown files. You write .claude/commands/review.md with instructions, and /review in that project triggers it. Nate uses this for repeatable tasks like "audit this workflow for security issues" or "generate test data for this schema".
Somewhere around this point in the course it clicked for me that Claude Code is not really a chat interface. It is more like a small operating system you assemble per project.

V. RAG (3:17:39 to 3:32:59)

Nate's RAG section is short and honest. For 90% of personal use cases you do not need a vector database. You need a folder of markdown files and Claude Code's built-in search.
His pattern: dump every document you care about into a /knowledge folder as markdown. Tell Claude Code in CLAUDE.md that this is your knowledge base. Use built-in Grep and Read. Done.
If you actually need vector search at scale, he shows a 5-minute setup with Supabase + pgvector + an n8n ingestion workflow. But the point he keeps coming back to is: try the dumb solution first.

VI. Turning n8n workflow into an app (3:32:59 to 4:12:42)

This section is where the course earns its title. Nate takes a working n8n automation (the lead enrichment one from earlier) and asks Claude Code to wrap it in a Next.js frontend so a non-technical user can use it without seeing n8n.
The prompt structure:
I have an n8n workflow at this webhook URL: [URL]
It takes a CSV upload and returns enriched leads.
Build me a simple web app where:
- User can upload a CSV
- See progress while processing
- Download results when done
Stack: Next.js, Tailwind, deploy to Vercel
Before you start, ask me 3 questions.
Claude Code asks the questions, builds the app, deploys to Vercel. About 35 minutes in the video. The result is rough but functional. I paused the video here and actually opened a terminal for the first time in three years.

VII. Website building and 3D sites (4:12:42 to 5:00:02)

The most YouTube-thumbnail part of the course and where I started skipping. Nate uses Three.js + React Three Fiber + Spline for 3D landing pages. The results look like every AI portfolio site from 2024: impressive at first, generic after 30 seconds. Skip unless you ship marketing pages.
One useful tip: paste a screenshot of a site you like directly into Claude Code and ask it to build something similar. Vision is now good enough that style transfer mostly works.

VIII. APIs and MCPs (5:00:02 to 5:28:16)

If you only watch one hour of the course, watch this one.
MCP (Model Context Protocol) is Anthropic's standard for connecting Claude to external tools. An MCP server exposes tools and data sources to Claude. MCPs Nate covers:
n8n MCP            reads your n8n nodes and templates
GitHub MCP         reads/writes your repos
Notion MCP         manages your Notion workspace
Google Calendar    sees your schedule
Gmail MCP          reads and drafts email
Make MCP           same as n8n MCP, for Make. com
Install pattern: get an API token, run one command in Claude Code to register the MCP, restart. Nate walks through the n8n MCP install in detail. The pattern transfers to the others.
The thing nobody else explains clearly: MCPs are not magic. They are typed function calls. Claude calls the function, MCP server runs it, result comes back. Once you see it is RPC with extra steps, the mysticism evaporates.

IX. Google CLI (5:28:16 to 5:39:42)

Short detour. Nate's honest take after using both Gemini CLI and Claude Code: Gemini is faster, free tier is more generous, Claude Code is meaningfully better at multi-step agentic work. He uses both, picks based on the task. For long autonomous sessions, Claude Code wins. For quick one-shots, Gemini saves you money.

X. Building your own executive assistant (5:39:42 to 6:08:03)

The section I rewatched twice. Nate builds a personal AI executive assistant from scratch in 27 minutes. Three layers: CLAUDE.md for identity (who you are, your preferences, what NOT to do), .claude/skills/ for repeatable processes (email-handling, calendar-management, daily-briefing), and .claude/agents/ plus knowledge/ for delegated work and persistent context.
You run it from terminal each morning. Say "morning brief". It reads your calendar, checks email, looks at active projects, produces a one-page summary with prioritized actions. Under 30 minutes to set up live.
The assistant itself is fine but not the takeaway. What I actually grabbed from this section is the four-folder pattern: CLAUDE.md for identity, skills for processes, subagents for delegated work, knowledge for context. Same structure works for a writing assistant, a code reviewer, anything else you want Claude to act like a person on rather than chat with.

XI. Skills (6:08:03 to 6:51:30)

If I had to pick one thing in Claude Code that changed the most in 2026, it would be skills. Nate spends 43 minutes on them and it is justified.
A Skill is a markdown file in .claude/skills/skill-name/SKILL.md that teaches Claude how to do a specific thing. When the task matches the skill, Claude loads the file automatically.
Two types of skills, and this distinction is the key insight:
Capability uplift skills give Claude an ability it does not have on its own. Web scraping, real PDF generation, browser automation. Without the skill, Claude cannot do the task. With it, it can.
Encoded preference skills capture how YOU want a task done that Claude already knows how to do. "How we format weekly status updates". "How we review NDAs". "Our git commit message format". Claude already knows what these things are. The skill encodes your specific way.
Most people start by trying to write capability uplift skills and fail because they are hard. Start with encoded preference skills. They are easier, more useful, they compound.
The biggest community skill library is obra/superpowers on GitHub (now over 94,000 stars, officially accepted into Anthropic marketplace). It is a complete multi-agent development workflow as a skill collection. If you are serious about Claude Code, this is the first repo to clone.
Repo:
https://github.com/obra/superpowers

XII. Sub-agents (6:51:30 to 7:11:20)

Subagents are isolated Claude instances spawned by the main session. Own context window, own work, return only a summary.
Long sessions degrade. If you ask main Claude to "research these 20 companies", it dumps 20 web pages into your context. Spawn a researcher subagent and it returns "top 3 fits and why" in 200 tokens.
Setup is a markdown file with frontmatter:
---
name: researcher
description: Researches companies and returns summaries
tools: [WebSearch, WebFetch, Read]
model: opus
---

You are a research specialist. Given a list of companies,
return a structured summary: size, recent funding, pain
points, decision maker contacts.
Save as .claude/agents/researcher.md. Main Claude can now delegate research to it.
The pattern Nate uses most: one main agent (you talk to it), three to five specialized subagents (researcher, writer, reviewer, executor). The main agent orchestrates. The subagents do specific work in their own context.

XIII. Agent teams (7:11:20 to 7:27:30)

Nate builds a "marketing team" of 6 subagents (strategist, copywriter, designer, distributor, analyst, manager) and gives them one task: "launch a new product feature". 20 minutes of orchestration produces a launch plan, ad copy, email sequence, and analytics setup.
The output looks impressive on first watch. Second watch you notice the plan is generic, the copy needs heavy editing, and the analytics is GA4 boilerplate. So the technique works but the output is only as good as your subagent prompts, which in the demo are not great. I would file this under "agent teams are possible" rather than "agent teams replace humans".

XIV. Browser automation (7:27:30 to 7:42:30)

Claude in Chrome (the official extension) plus Claude Code plus /chrome. You connect Claude Code to your browser session and it can navigate, click, fill forms, read DOM.
Nate's use case: scraping a list of business leads from an event page that does not have an API. Claude opens the page, paginates, extracts data, saves to CSV. About 15 minutes for 200 leads.
Important caveat Nate skips: the Chrome extension is in beta and Anthropic has flagged prompt injection as an active risk. Do not run it on sites with sensitive data (banking, healthcare, confidential email). Use it for public scraping, form filling on test sites, low-stakes browser tasks.

XV. Permissions and context management (7:42:30 to 7:50:09)

Eight minutes that save headaches.
Claude Code asks permission before every file write, bash command, and external call by default. This is annoying so you turn it off. Then it does something destructive and you turn it back on.
Nate's middle ground: --permission-mode auto for trusted operations (reading files, running tests). Manual approval for risky ones (writing to git, deploy scripts). Set per project in CLAUDE.md.
Context rule: when your context bar hits 60% used, save your progress as a markdown file in the project, run /clear, start a fresh session pointing Claude to the saved file. Buys you another full window every time.

XVI. GitHub and Worktrees (7:50:09 to 7:56:45)

The useful trick is git worktrees for parallel Claude Code sessions.
A worktree lets you have multiple working copies of the same repo, each on a different branch, in different folders. Open one Claude Code session per worktree. Claude works on feature A in one terminal and feature B in another, no context bleed, no merge conflicts mid-session.
git worktree add ../feature-b feature-b-branch
cd ../feature-b
claude
For solo developers this is overkill. For anyone running multiple workstreams it changes the game.

XVII. Fun hacks (7:56:45 to 8:25:06)

The two tricks worth remembering:
Voice input. Speaking prompts is 4x faster than typing for long requests. Nate uses Glaido. Any voice-to-text tool works. Most people do not realize how much time they save until they try it for a week.
Screenshot as prompt. Paste a screenshot directly into Claude Code and ask "build this" or "fix this UI". Vision is now good enough that this works on real work, not just toys.
Everything else in the section is style preference.

XVIII. The selling AI mindset (8:25:06 to 8:39:41)

From here the course goes from technical to business and honestly I almost stopped watching. Glad I did not. The next two hours are the most valuable part for anyone trying to make money with this, and the part nobody else covers at this depth.
Nate's core mindset shift: you are not selling AI workflows. You are selling business outcomes.
A client does not care that you used Claude Code with n8n and three MCP servers. They care that their sales team got 5 hours back per week. Same workflow, two pitches:
Bad:    "I built an n8n workflow with Claude Code and OpenAI
        that takes inbound leads, enriches them via Apollo MCP,
        scores them with a custom prompt, drops them in your CRM"

Good:   "Your team spends 15 hours a week on lead research.
        I built something that does it in 20 minutes a day.
        At $50/hour that is $3,000 a month back to your team."
The technical work is the same. The pitch is what gets paid.

XIX. Finding clients (8:39:41 to 8:54:01)

Nate's actual playbook.
Where his clients come from:
  1. Inbound from YouTube content (largest source by far)
  2. Posts on X showing live builds
  3. Posts on LinkedIn with case studies
  4. His Skool community
Cold outreach is not his channel. He has tried it. It works. Content-driven inbound is 10x his lead source.
Starting from zero with no audience, the sequence:
  1. Build something for yourself first. This is your portfolio.
  2. Post it in public. Show the math: what it does, how much time it saves.
  3. DM five people in your network whose business has the problem your build solves.
  4. Offer to install free for the first two clients in exchange for a video testimonial and case study.

XX. First client in 7 days (8:54:01 to 9:14:56)

Case study of community member "Jerome" landing a $2,000 newsletter automation client in 7 days.

XXI. Pricing AI workflows (9:14:56 to 9:35:36)

The best 20 minutes of the course. Real numbers, real rationale.
Nate's rules:
Price against ROI, not against hours. If your workflow saves a team $4,000 a month, you can charge $4,000 once. Or $1,000 a month as ongoing maintenance. Or $8,000 with 3 months of support. Hours-based pricing caps your upside.
If more than 50% of prospects say yes, you are priced too low. A close rate of 30-40% means you are at the right price. 60%+ means clients are getting a steal.
Sales-related automations carry higher value than admin automations. Same hour of work, different price ceiling. An automation that books meetings is worth more than one that schedules them.
Retainer over one-time. $3,000 once is fine. $1,500/month forever is better. Build maintenance into the deal from day one.
His own four-agent breakdown from 2025 shows the rules in practice. Agent #1 was Personalized Outreach at $1,000 (he admits underpriced). Agent #2 was a Sales Agent at $4,000 (fair). Agent #3 was a Personal Assistant at $6,000 (should have been
$10K+
, he learned). Agent #4 was an AI Concierge at $12,000 (well priced). Total $23,000.
He explicitly says agent #3 was the lesson. Sales-related agent #4 priced 3x higher than admin-flavored agent #3 despite similar build complexity.

XXII. Delivering AI projects (9:35:36 to 9:58:55)

Most AI builders ship a workflow and then get on the phone every week answering "why did it break?". Nate's clean delivery framework:
  1. Documentation in the client's tools. Not your Notion. Their Confluence, their Slack canvas, their wiki. Meet them where they live.
  2. Loom walkthrough. A 5-minute video showing how the workflow runs, where the dashboard is, how to read errors. Send the Loom with the handover email.
  3. 30-day support window built into the price. After 30 days, support is hourly or via retainer.
  4. A self-healing wrapper. Same pattern from section III. The workflow monitors itself, reports failures, attempts auto-recovery. The client pings you only when auto-recovery fails.
  5. Quarterly review call. The upsell hook. Every 90 days you sit with the client, review what worked, propose the next workflow. This is how one-time projects become
    $5K-
    $20K/month retainers.
The retainer model is Nate's actual business. His marketing implies $231K in 30 days from this, which is contested in independent reviews. The verified numbers are smaller. But the structure he teaches is real and matches what works in AI consulting in 2026.

What the course misses

Three honest gaps.
No real discussion of failure modes. Claude Code is not perfect. It hallucinates file paths, confidently writes broken code, sometimes loops forever on edge cases. Nate barely touches this. Watch the course, then watch one or two videos of someone debugging a failed Claude Code session to balance the perspective.
The course is heavily n8n-coded. If you use
Make.com
, Zapier, or build custom, you can still apply 70% of the content but you have to translate. The MCP install steps, the workflow templates, the architecture patterns are n8n-first.
The income claims do not always match the documented work. Nate's marketing pushes $231K/month numbers. His documented agency client work is $23K total across 4 agents in 2025. Both can be true (course sales vs. agency work), but the marketing implication that anyone watching can replicate the headline number is overstated.

What to do after

1. Install Claude Code, run /init in any folder

3. Build one workflow using the WAT framework
4. Install one MCP server (n8n or GitHub or Notion)
5. Write one skill, one subagent, one custom command
6. Post the result in public
