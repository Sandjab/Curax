In local plan mode, that means your terminal is locked for minutes. Sometimes longer. That’s when I tried /ultraplan for the first time.

Within seconds, my terminal gave me a link and said “go check this in your browser.” My terminal was free again. I went back to fixing a bug in another project while Claude was busy planning in the cloud.

It felt like going from a text file to Google Docs.

What Ultraplan Actually Does (In Plain English)

Here’s the simple version. Ultraplan takes your planning task and sends it to the cloud. Claude drafts the plan on Anthropic’s servers using Opus 4.6 — while your local terminal stays completely free for other work.

https://code.claude.com/docs/en/ultraplan

When the plan is done, you open it in your browser at claude.ai. You get a rich review interface where you can highlight specific paragraphs and leave inline comments. You can drop emoji reactions on sections you like or flag parts that need work. There’s even an outline sidebar so you can jump between sections quickly.

Think of it this way. Local plan mode is like drafting an architecture doc in Notepad. Ultraplan is like drafting it in a proper collaboration tool where you can actually give targeted feedback.

The best part? When you’re happy with the plan, you choose where to execute it. You can either let Claude build it right there in the cloud and open a pull request. Or you can “teleport” the plan back to your terminal and execute it locally with full access to your environment.

That teleport feature is what sold me. You get cloud-powered planning without giving up local control.

Three Ways to Launch It (Pick Your Favorite)

Getting started with Ultraplan is stupidly simple. You have three options.

The first way is the direct command. Just type /ultraplan followed by what you want to plan. Something like /ultraplan migrate the auth service from sessions to JWTs. Clean and explicit.

The second way is even easier. Just drop the word “ultraplan” anywhere in a normal prompt. Like “I need an ultraplan for refactoring the payment module.” Claude picks up the keyword and sends it to the cloud automatically.

The third way is my personal favorite. Start planning locally first. When Claude finishes the local plan and shows you the approval dialog, there’s a new option: “No, refine with Ultraplan on Claude Code on the web.” This lets you take a rough local plan and send it to the cloud for deeper refinement. It’s like writing a rough draft on paper and then editing it on a proper screen.

One thing to know — Ultraplan needs a GitHub repository and a Claude Code on the web account. If you’re on a Pro, Max, Team, or Enterprise plan, you’re good to go.

The Real Difference: Better Plans, Faster

I ran a side-by-side test. Same prompt. Same project. Local plan on one side, Ultraplan on the other.

The local plan took noticeably longer to finish. And when it was done, the plan was decent — but it missed some edge cases in the dependency chain.

Ultraplan finished faster. The plan was more thorough. It caught dependencies that local mode missed. The structure was cleaner. The implementation steps were more logical.

But here’s what really surprised me. When I actually built from each plan, the Ultraplan version produced better results. The code had fewer bugs. The architecture was more solid. Small differences, but they added up fast.

Why? I think it comes down to one thing: better planning leads to better code. We already know this in theory. But Ultraplan makes it real in practice. When Claude has more compute power, more time, and a dedicated environment for planning, the quality goes up. Simple as that.

The Workflow That Changed Everything

Here’s exactly how I use Ultraplan now for any complex task.

I start by typing /ultraplan with a detailed prompt about what I need. Claude spins up a cloud session, and my terminal shows a status indicator. I go work on something else — maybe reviewing PRs, maybe writing docs, whatever.

When I see the status change to “ultraplan ready,” I click the link and open the plan in my browser. I read through it carefully. If something looks off, I highlight that section and leave an inline comment. If a section looks good, I hit it with a thumbs up emoji.

Then I tell Claude to address my comments. It revises the plan. I review again. Maybe one more round. When I’m satisfied, I hit “Approve plan and teleport back to terminal.”

My terminal gets the final plan with three options. I usually pick “Implement here” to inject the plan right into my current conversation. Claude starts building immediately, following the detailed plan it spent real time creating.

The result? Cleaner code, fewer iterations, less time debugging weird issues that came from a half-baked plan.

One Important Catch

Ultraplan is in research preview right now. That means things might change. There might be bugs. Anthropic is still iterating on it based on feedback.

Also, when you launch Ultraplan, it creates a snapshot of your repository at that moment. The cloud session works from that snapshot — it doesn’t see changes you make after launching. So don’t start editing files and expect Ultraplan to pick up those changes mid-plan.

And one more thing — if you’re using Remote Control, it disconnects when Ultraplan starts. Both features use the claude.ai/code interface, and only one can be connected at a time. Just something to keep in mind.

Should You Use It?

If you’re doing simple, quick tasks? Probably not. Local plan mode is fine for small stuff.

But if you’re planning anything complex — a big refactor, a service migration, an architecture change — Ultraplan is worth trying. The richer review interface alone makes it valuable. Add in the faster planning speed and the ability to keep working while Claude thinks? It’s hard to go back.

I tested it multiple times now. Every time, the Ultraplan version produced a more thorough, more detailed plan than local mode. The difference isn’t always huge. Sometimes it’s subtle. But those subtle differences in planning lead to real differences in the final code.

Good planning isn’t glamorous. It’s not the exciting part of coding. But it might be the most important part. And Ultraplan makes it significantly better.

Give it a try. Type /ultraplan on your next big task. Let Claude think in the cloud while you keep working. Then review the plan in your browser like a real collaboration tool instead of squinting at your terminal.

I think you’ll be surprised.
