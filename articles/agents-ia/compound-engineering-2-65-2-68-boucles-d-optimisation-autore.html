[New] /ce:optimize, autoresearch-style optimization loops

This one's been cooking for a while By
@huntharo
, a community contributor.
/ce:optimize is an iterative optimization loop inspired by
@karpathy
‘s autoresearch, generalized for multi-file code changes and non-ML domains.
The idea: define a measurable goal, build measurement scaffolding, then let it run a long loop that tries many hypotheses in parallel, measures each, keeps improvements, and converges toward the best result. Useful for things like tuning system prompts, improving vector clustering quality, optimizing search relevance, reducing build times, or comparing code solution approaches. The kind of work where no single change gets you there and you need 50+ iterations with memory of what was tried.
It handles both hard metrics (build time, test coverage) and qualitative targets. For qualitative stuff like clustering coherence or search relevance, it uses LLM-as-judge with stratified sampling so you're not just chasing a misleading proxy metric. Experiments run in parallel across up to 6 git worktrees or Codex sandboxes with crash recovery baked in, since these sessions can run for hours.
First real test run by
@huntaro
: clustering optimization, ~90 minutes, 16 experiments, coverage went from 31% to 72%.

[New] ce:ideate v2, ideation that works beyond code

Before this, ce:ideate forced everything through a repo/code lens. Ideating about naming, pricing, narrative, or a personal decision? Too bad, you got software-flavored frames and generic output.
v2 classifies the subject of your ideation in two steps: is this grounded in the current repo or elsewhere, and is it software or non-software? Then routes to the right facilitation path. 6 mode-symmetric frames replace the old software-only set. Non-code ideation can terminate cleanly without forcing you past your natural stopping point into a brainstorm > plan > work chain that doesn't make sense.
You can even paste screenshots in of UI and ask it things like `/ce:ideate how can I improve conversion?` even if the screenshot isn't related to the repo you're in. Flexibility!
Note: There's also a new web-researcher agent that provides external grounding (prior art, adjacent solutions, market signals, cross-domain analogies) to support our skills for topics where your codebase isn't the primary source of context.

[New] Human-in-the-loop with Proof, everywhere

Big theme this week: giving you more moments to review and steer agent work before it ships.
/ce:polish-beta is a new phase that sits between ce:review passing and merge. It starts a dev server from your `.claude/launch.json`, generates a user-testable checklist from the diff surfaces, lets you mark items that need craft fixes, and dispatches polish sub-agents in parallel. If individual items are too big, it seeds stacked PRs. If the whole batch is oversized, it generates a replan. Credit to
@kieranklaassen
for this one.
Proof
review loops are now wired into ce:brainstorm, ce:plan, and ce:ideate through a shared workflow. We love the terminal but sometimes seeing rendered markdown is nice 😀 You open your doc in Proof, annotate with comments, and the agent reads them, applies fixes, and syncs the reviewed markdown back to disk. One consistent handoff menu across all three skills.

[New] /ce-setup, onboarding that actually works

`/ce-setup` runs a single-pass health check across CLI tools, project config, and dependencies, then offers to install what's missing and bootstrap your config files. One command to go from fresh install to working environment To optimize your CE experience

[New] /ce-pr-description, centralized PR descriptions

Any skill that needs a PR description can now delegate to ce-pr-description. Give it a natural-language prompt with optional PR reference and it returns a structured title and body. Works across repos too: paste a URL from a repo you don't even have cloned locally and it'll describe the PR via the GitHub API. Our very own git-commit-push-pr skill now delegates to it, so there's one place to evolve writing quality.

[New] /ce-release-notes, "what shipped?"

Run `/ce:release-notes` bare and you get the last 5 CE plugin release notes. Add a question like `/ce:release-notes what happened to deepen-plan?` and it searches the last set of releases with version citations and PR-level grounding. Nice for catching up after a week off or checking when a specific feature landed.

[Fixed] Reliability and safety

A handful of fixes worth mentioning across these releases: reviewer agents are now restricted to read-only tools (no more accidental writes during review), ce:work and ce:work-beta have safety checks for parallel subagent dispatch, ce:review always fetches the base branch to prevent stale merge-base comparisons, and git-commit-push-pr now writes descriptions as net result instead of a changelog. Also dropped `claude-permissions-optimizer` in favor of the built-in `/less-permission-prompts` That Anthropic just launched.
….Side note on naming: yes, the colon vs hyphen inconsistency is still there (ce:work vs ce-sessions). We're setting up for a broader skill and agent rename in v3 where everything moves to a consistent `ce-` prefix among other big features coming. Thanks for being patient!
