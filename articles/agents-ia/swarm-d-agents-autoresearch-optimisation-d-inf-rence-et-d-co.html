LLMs Slow Down the Longer You Talk to Them

Every token a model generates, attends over the entire conversation.
That history lives in the KV cache. As it grows → more memory to read → slower inference.
We tested
Gemma 4 31B
with int4 KV cache (so it fits on consumer hardware):
  • Start: 10.8 tok/s
  • After a few hundred tokens: 7.2 tok/s
→ 33% slowdown → keeps getting worse as context grows
This is the hidden tax of long conversations.

The Results

Within a weekend, our agent swarm built a fused int4 attention (SDPA) kernel (inspired by
@GoogleResearch
's
TurboQuant)
.
With the fused kernel:
  • 10.4 → 9.8 tok/s
  • throughput stays nearly constant
Flat vs degrading decode speed
Same model. Same hardware. Completely different scaling behavior.
The bottleneck was memory efficiency - creating and discarding large temporary data every token.

Why This Matters

Most inference work optimizes for throughput at a fixed context length.
But in real usage, context grows, and how latency scales with it matters just as much:
  • longer conversations remain usable
  • latency is more predictable over time
  • memory bandwidth pressure is reduced
The longer the conversation → the bigger the win.

What We Did

We gave the agent swarm one objective:
Make Gemma 4 31B run fast on Apple Silicon and eliminate context-dependent slowdown.

@ensue_ai

Experiments that the agents explored and documented within 48 hours

Insight: TurboQuant Breaks with Models that use Learned Scaling

We implemented
TurboQuant (ICLR 2026)
, a KV cache compression technique combining
PolarQuant
and
QJL
.
In 3.5 hours, agents built the first-ever Metal implementation: 10 GPU compute shaders ported from NVIDIA's CUDA, iterated through 5 generations, 65 experiments completed.
We ran it. And it produced gibberish.
TurboQuant works with fixed attention scaling. But Gemma 4 uses learned scaling (QK-norm).
That changed everything.
  • Angular quantization introduces small errors
  • Softmax amplifies it exponentially
  • Over 60 layers → output collapses
→ This was not in the paper → Only shows up at this scale + architecture
Implication:
If a model uses learned attention scaling, angular quantization methods can fail in ways that aren’t visible in smaller benchmarks.
Quantization performance is not just about bitwidth or method, it also depends on how attention is parameterized.
