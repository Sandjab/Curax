Think Anywhere in Code Generation

Lecture Critique d'Article

Objectif et contexte

Le travail s'attaque à une limite structurelle des LLM de raisonnement actuels (o1, DeepSeek-R1, Kimi K2) appliqués à la génération de code : le paradigme upfront thinking confine la délibération à un bloc initial <think>, avant toute écriture de code. Les auteurs identifient deux faiblesses concrètes de ce schéma. D'abord, la complexité d'un problème algorithmique ne se révèle souvent qu'au moment de l'implémentation (bug d'indexation 0-based/1-based dans un DP, cas limites). Ensuite, l'effort de raisonnement est réparti uniformément en amont, alors que la difficulté cognitive varie fortement entre du boilerplate et une décision algorithmique critique.

La contribution principale, THINK-ANYWHERE, formalise un mécanisme qui entrelace des blocs <thinkanywhere> à des positions de token arbitraires, choisies dynamiquement par le modèle. Le code exécutable est obtenu en retirant ces blocs, qui restent invisibles à l'exécution mais guident la génération.

Méthodologie

Le pipeline tient en deux étages. Un cold-start supervisé d'abord : environ 5 000 exemples sont synthétisés par Gemini 2.5 Flash, filtrés sur la validité du formatage, puis utilisés pour du fine-tuning LoRA sur Qwen2.5-Coder-7B-Instruct. Cette phase installe le motif d'invocation, pas la pertinence des positions.

Un étage RLVR ensuite, via GRPO, avec un reward hiérarchique combinant une composante structurelle Rstruct (vérifie la présence d'un bloc initial <think> et d'au moins un <thinkanywhere>, pondérée α = 0,1) et une composante fonctionnelle Rcorrect basée sur le passage des cas de test. L'entraînement tourne sur 14K problèmes du dataset Skywork, 8 A100 40G, batch 128, 2 époques, rollout de 8 échantillons à 4096 tokens.

Les auteurs testent également une variante à token dédié (THINK-ANYWHERE*) avec une initialisation d'embedding sémantiquement composée : 0,5 × moyenne(ethink, eany, ewhere) + 0,5 × e<im_start>. Cette variante suit une procédure de cold-start en deux phases (alignement d'embeddings d'abord, fine-tuning joint ensuite).

Résultats principaux

Sur quatre benchmarks (LeetCode, LiveCodeBench, HumanEval, MBPP), THINK-ANYWHERE atteint 70,3 % de moyenne pass@1 contre 61,0 % pour le modèle de base et 68,4 % pour GRPO standard. Le gain le plus marqué est sur LeetCode (+18,8 points vs base, +2,1 vs GRPO). Le modèle généralise hors distribution vers les benchmarks mathématiques (AIME 2024, AIME 2025, HMMT 2025) sans avoir vu de données mathématiques : pass@1 AIME 2024 passe de 5,3 % à 17,3 %, alors qu'il n'a été entraîné que sur du code.

Les ablations sont instructives. Le cold-start seul s'effondre à 47,9 % sur LeetCode (−21,5), le RLVR seul à 63,4 % (−6,0). Le raisonnement par ligne plutôt que par token perd 2,2 points, confirmant l'intérêt de la granularité fine. Le retrait de la phase initiale <think> ne coûte que 2,8 points, suggérant que la valeur ajoutée réside bien dans les blocs intra-code. Une variante Padding Thinking (contenu des blocs remplacé par du padding) chute de 1,8 point : une part des gains provient de la simple identification des positions, le reste du contenu raisonné.

L'analyse d'interprétabilité est le point fort de l'étude. Le modèle déclenche préférentiellement des blocs à haute entropie locale (Figure 2a), et les positions syntaxiques ciblées (assignations, returns, conditions via AST parsing) coïncident avec des décisions algorithmiques chargées. Contre-intuitivement, THINK-ANYWHERE consomme moins de tokens que GRPO ou CoT : la phase <think> initiale se raccourcit substantiellement (215 tokens vs 309 pour GRPO sur HumanEval), et le surcoût des <thinkanywhere> (22,5 tokens en moyenne) ne compense pas cette réduction.

Discussion et limites

Plusieurs zones d'ombre méritent d'être pointées. L'évaluation utilise systématiquement du greedy sampling (température 0), ce qui élimine la variance mais ne renseigne pas sur la stabilité des gains. Aucun test statistique n'est proposé pour départager THINK-ANYWHERE de CodeRL+ (66,8 vs 70,3), et les écarts sur certains benchmarks (HumanEval : 91,5 vs 90,9) sont dans le bruit plausible d'un run unique.

La variante à token dédié THINK-ANYWHERE* obtient 70,0 %, quasi identique à la version texte (70,3 %). Les auteurs l'attribuent à la quantité limitée de données post-training, mais cela questionne le bénéfice réel de l'ingénierie d'embeddings proposée. Le rationnel théorique (désambiguïsation sémantique du délimiteur) n'est pas validé empiriquement.

Le reward structurel force la présence d'au moins un bloc <thinkanywhere>, ce qui introduit un biais systématique vers l'invocation. L'ablation No Upfront Thinking (−2,8 points) suggère que la phase initiale reste utile, mais les auteurs ne testent pas la symétrique : forcer zéro <thinkanywhere> tout en conservant le reste du pipeline. La comparaison propre avec un GRPO recevant le même budget de tokens manque également.

La transférabilité aux benchmarks mathématiques est impressionnante en magnitude (+12 points pass@1 sur AIME 2024), mais repose sur un modèle de base faible (5,3 %). À ces niveaux, les gains absolus de quelques bonnes réponses sur un petit benchmark (30 problèmes pour AIME) sont fragiles.

Reproductibilité

Le code source et les données sont annoncés sur GitHub (jiangxxxue/Think-Anywhere). Les hyperparamètres d'entraînement sont documentés (batch, learning rate, nombre d'époques, framework VeRL). Le modèle de base (Qwen2.5-Coder-7B-Instruct) et le dataset d'entraînement (Skywork) sont publics. Les données de cold-start synthétisées par Gemini 2.5 Flash ne sont pas explicitement publiées, mais le protocole de construction est décrit. Le prompt template est fourni intégralement (Table 1). La reproductibilité est correcte pour un preprint, sans atteindre les standards de publications comme les rapports DeepSeek-R1.

Impact et applications

L'idée d'un raisonnement invocable à granularité token plutôt qu'en bloc amont cristallise une tendance déjà visible (Interleaved Thinking de Xie et al. 2025, TwiG pour la génération visuelle). La contribution n'est pas tant conceptuelle que méthodologique : montrer qu'un cold-start SFT + RLVR outcome-based suffit à faire émerger des patterns de raisonnement adaptatif sans supervision explicite sur les positions. C'est un résultat d'ingénierie RL cohérent avec les observations récentes sur l'efficacité des rewards vérifiables.

Les applications pratiques concernent au premier chef les petits modèles de code : le gain de +13,9 points sur Qwen2.5-Coder-1.5B suggère que THINK-ANYWHERE compense partiellement une capacité paramétrique limitée par une allocation dynamique de calcul. L'économie de tokens par rapport à GRPO ouvre un cas d'usage en inférence à budget contraint.

Positionnement dans la littérature

Le papier se situe à l'intersection de trois lignées. La première, post-training RL pour le code (Skywork-OR1, CodePRM, CodeBoost, CodeRL+), auxquelles THINK-ANYWHERE ajoute une dimension structurelle au-delà de la seule optimisation du reward final. La deuxième, interleaved reasoning (Xie et al. 2025, PlanTain de Liang et al. 2025), dont il se distingue par l'absence de sous-étapes imposées : le modèle décide lui-même quand penser. La troisième, pause tokens et calcul implicite (Goyal et al. 2024, Pfau et al. 2024), avec lesquels il partage l'idée que des tokens non-informatifs peuvent porter du calcul utile — l'ablation Padding Thinking l'illustre explicitement.

Le rapprochement avec Meta-Chain-of-Thought et les architectures récurrentes de type think-anywhere mentionnées dans la taxonomie des domaines est direct. Ce travail apporte une preuve empirique qu'un simple token delimiter suffit à déclencher une forme d'auto-allocation du calcul, sans changement d'architecture.
