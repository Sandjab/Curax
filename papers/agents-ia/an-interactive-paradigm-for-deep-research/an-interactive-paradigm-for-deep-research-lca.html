An Interactive Paradigm for Deep Research

Lecture Critique d'Article

Objectif et contexte

Les systèmes de deep research basés sur les LLM (OpenAI Deep Research, Gemini Deep Research, GPT-Researcher, Search-o1, etc.) suivent un schéma rigide : une phase de cadrage initial (au mieux une question de clarification), puis un long run autonome qui produit un rapport monolithique. Si l'intention de l'utilisateur évolue en cours d'exécution — ce qui arrive régulièrement sur des tâches long-horizon — le système ne peut pas se réaligner. STEER cherche à corriger ce défaut structurel en introduisant un mécanisme de pause adaptative et un modèle de persona qui se met à jour pendant la session.

Le positionnement est défendu via le Tableau 1 du papier, qui croise trois capacités (mid-process steering, adaptive pause decision, live persona modeling) face à 11 systèmes existants. STEER est le seul à combiner les trois.

Méthodologie

Le framework repose sur trois modules opérant sur un arbre de recherche T = (N, E) construit incrémentalement jusqu'à une profondeur D :

  • Diversity-aware exploration : sélection MMR gloutonne d'un sous-ensemble de K questions de suivi à chaque nœud frontière, avec une question « wild-card » imposée pour éviter le collapse thématique.
  • Pause decision : règle coût-bénéfice ∆EV(n*) > C(n*) qui compare l'utilité espérée d'une pause (basée sur des bornes upper/lower de confiance, inspirées de lil'UCB) au coût d'interruption. Le coût C(n*) = C₀ · (1 + pauses_j / Tol_j) augmente avec la fréquence des pauses dans une direction.
  • Branch utility : combinaison pondérée de trois signaux normalisés sur [0,1] — ∆Align (gain d'alignement avec les aspects inférés), Explore (bonus UCB sur les facettes sous-explorées), InfoGain (nouveauté sémantique vs centroid des learnings accumulés).
  • Persona modeling : persona vivant Ṗ(n*) = (p̂_text(n*), Â(n*)) mis à jour à chaque pause à partir des sélections et propositions utilisateur.

L'évaluation s'appuie sur 200 query-persona pairs dérivés du dataset Researchy Questions, avec personas générés via le paradigme ALOE filtré par SBERT (seuil de similarité 0,65) et aspects (5-8 par persona) générés selon Salemi & Zamani (2025). Les comparaisons utilisent GPT-4o comme backbone unique, arbre fixé à profondeur 3 × largeur 3, avec un User Agent simulé conditionné sur la persona complète pour produire les signaux de steering. Le juge automatique est gpt-4.1-mini.

Résultats principaux

STEER atteint 85,70 sur l'alignement contre 79,48 pour le meilleur baseline (GPT-Researcher avec persona complet), soit un gain absolu de 6,22 points et relatif de 7,83 %. Le gain monte à 22,80 % face à OpenDeepResearch sans persona. STEER reçoit uniquement la première phrase du persona, là où les baselines reçoivent la persona complète — un point crucial pour l'applicabilité réelle (contraintes de privacy, onboarding).

Sur les métriques de qualité générale (Clarity, Depth, Breadth, Insight, Balance) issues de DeepResearchGym, STEER mène sur Breadth (91,29) et Balance (84,19) mais reste légèrement en-dessous du modèle propriétaire o4-mini-deep-research sur Depth et Insight.

L'étude humaine collecte 58 annotations pairwise auprès de 12 annotateurs (étudiants gradués NLP/CS). STEER remporte 86-90 % des comparaisons sur Alignment, 83 % sur Focus, avec des gains significatifs sur Coverage (+0,623, p=3,05e-12) et Findability (+0,690, p=1,64e-11) sur des échelles 0-2. Les coefficients Gwet's AC1 (0,639 pour Alignment, 0,475 pour Focus) indiquent un accord substantiel à modéré.

Les ablations confirment le rôle des trois signaux d'exploration : retirer la diversification MMR cause les chutes les plus larges (depth, breadth, focus), retirer InfoGain dégrade surtout l'alignement, retirer Explore dégrade le focus. Le sweet spot empirique se situe à C₀ = 0,7 (équilibre alignement / charge utilisateur).

Discussion et limites

Plusieurs faiblesses méthodologiques affaiblissent les conclusions. Le User Agent de simulation est par construction un oracle quasi-parfait : précision > 0,97 sur tous les C₀, fidélité totale à la persona-cible, pas de fatigue ni d'incohérence. Les auteurs reconnaissent que cette validation surestime probablement les performances en conditions réelles, où les utilisateurs donnent des réponses partielles, contradictoires ou abandonnent.

La corrélation Pearson entre le juge LLM (gpt-4.1-mini) et les annotations humaines au niveau aspect est r = 0,34 (p < 0,0001) — statistiquement significative mais qualitativement modérée. Les 22,80 % de gain en alignement automatique doivent donc être lus avec prudence : l'étude humaine sur 58 paires valide directionnellement, mais l'écart numérique exact n'est pas garanti.

Le panel d'annotateurs (12 étudiants NLP/CS) est homogène et susceptible de biais favorables aux outputs structurés des systèmes ML. Le blinding est imparfait — les auteurs l'admettent — et un fingerprint stylistique entre STEER et les baselines pourrait fuiter l'identité du système.

L'évaluation utilise GPT-4o pour tous les agents et fixe l'arbre à 3×3, ce qui empêche de tester comment STEER scale avec la profondeur (où le paramètre Tol devient pertinent, comme les auteurs le notent eux-mêmes). Aucune analyse de runtime ou latence n'est fournie, ce qui est problématique pour un système conçu autour de l'interaction : combien de temps un utilisateur attend-il entre deux pauses ?

Les personas eux-mêmes sont synthétiques, générés à partir du dataset ALOE avec filtrage SBERT à 0,65. Cette borne supérieure de similarité ne garantit pas la représentativité des intentions de recherche réelles.

Reproductibilité

Point fort du papier. Les prompts complets (Planning, Search Result Processing, Persona Checklist Inference, Persona Modeling, Report Generation) sont fournis dans les annexes K-N. Le pipeline de génération de données est documenté. Les auteurs annoncent la release d'une persona-query evaluation suite. Les hyperparamètres sont explicités (C₀, Tol, λ_exp = λ_info = 0,5, D = 3, K = 3, seuil SBERT = 0,65). L'algorithme MMR diversifié est donné en pseudo-code dans l'annexe C.

Réserves : pas de code disponible publiquement au moment de la soumission, dépendance à des APIs propriétaires (GPT-4o, o4-mini-deep-research, gpt-4.1-mini) qui peuvent évoluer et compromettre la reproductibilité future.

Impact et applications

La proposition adresse un trou réel : les systèmes de deep research actuels brûlent du compute sur des trajectoires désalignées. Une politique de pause apprenable et un persona évolutif sont des composants génériques applicables au-delà du web research — les auteurs citent la découverte scientifique (NovelSeek, AgentRxiv), le conseil financier (FinCon), et le legal research comme cibles naturelles.

Le formalisme branch utility = ∆Align + λ_exp · Explore + λ_info · InfoGain est modulaire : ajouter des termes (factuality, citation quality, safety) reste trivial. C'est la principale contribution structurelle, davantage que les chiffres absolus de performance.

Positionnement dans la littérature

Le papier se positionne explicitement contre deux familles : les pipelines multi-agents one-shot (ManuSearch, Search-r1, DeepResearcher) et les frameworks RL-trained (Search-o1, R1-Searcher). Le concurrent direct est EDR (Prabhakar et al., 2025), qui propose aussi un steering mid-process mais sans politique de pause adaptative ni persona vivant. STEER complète également la ligne de travaux sur la clarification (STaR-GATE, Robots that ask for help, Action-Based Contrastive Self-Training) en passant d'une décision locale « ask vs answer » à une politique globale sur un arbre de recherche.

Le lien avec les bandits multi-armed (UCB, lil'UCB) est honnête : les auteurs précisent qu'ils n'invoquent pas les garanties de regret stationnaires et utilisent UCB comme prior d'optimisme plutôt que comme algorithme classique. Cette précaution intellectuelle est appréciable.
