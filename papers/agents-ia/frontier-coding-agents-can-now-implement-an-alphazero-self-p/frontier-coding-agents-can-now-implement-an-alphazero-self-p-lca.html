Frontier Coding Agents Can Now Implement an AlphaZero Self-Play Machine Learning Pipeline For Connect Four That Performs Comparably to an External Solver

Lecture Critique d'Article

Objectif et contexte

Le papier propose un benchmark de proof-of-concept pour mesurer la capacité d'agents de coding frontières à implémenter de bout en bout un pipeline ML inspiré d'AlphaZero, à partir d'une description de tâche minimale plutôt que du papier original. La motivation est explicitement reliée à la détection précoce d'auto-amélioration récursive (RSI) : si les agents peuvent répliquer des avancées passées sur des descriptions courtes, ce serait un signal avancé d'accélération des capacités de R&D ML.

Le choix de Connect Four comme terrain d'évaluation s'appuie sur trois propriétés exploitables : coût computationnel faible (entraînement sur GPU consumer), critère de réussite objectif via le solveur Pascal Pons, scalabilité naturelle vers des jeux à espace d'état plus large.

Méthodologie

Quatre agents évalués (Claude Opus 4.7, Claude Opus 4.6, GPT-5.4 via Codex, Gemini 3.1 Pro via Gemini CLI), chacun sur 8 essais avec budget de 3 heures, sandbox Docker dédié par CLI et configuration agent-spécifique soigneusement documentée (whitelists Squid, iptables, bind mounts de credentials, gestion des prompts d'autorisation). Le protocole inclut un tournoi round-robin de N=49 joueurs (48 essais + solveur Pons comme ancre) avec quatre parties par appariement ordonné.

L'évaluation utilise un modèle Bradley-Terry par maximum de vraisemblance, ancré à 2000 sur le solveur Pons, avec rééchelonnage Elo (différence de 400 = ratio 10:1). Les tests statistiques sont non-paramétriques (Kruskal-Wallis, Mann-Whitney U avec correction Holm, Fisher exact pour binaires, Brown-Forsythe pour les variances), choix justifié par les petites tailles d'échantillon et la non-normalité.

Une sonde exploratoire de 16 essais supplémentaires sur GPT-5.4 croise deux stratégies de prompting (« hobbyist » court vs « hobbyist + alerte RSI ») et deux conteneurs (Docker vs Ubuntu hobbyiste avec fichiers personnels prépopulés), à raison de quatre essais par cellule.

Résultats principaux

Opus 4.7 domine clairement : 7/8 essais gagnent contre Pons en premier joueur, avec un score Bradley-Terry moyen de 1938, certains essais dépassant même les 2000 du solveur (en exploitant mieux que Pons les positions de second joueur via le self-play). Opus 4.6 suit à 1553 (2/8 victoires), GPT-5.4 à 1214 (0/8), Gemini 3.1 Pro à 495 (0/8) avec une variance significativement plus large (Brown-Forsythe p=0.003 vs Opus 4.7).

L'écart Opus 4.7 vs GPT-5.4 et vs Gemini reste significatif après correction Holm (p=0.005 et p=0.001). L'écart intra-famille Opus 4.7 vs 4.6 est marginal (p=0.021 brut, p=0.062 corrigé). Le spread global de ~2400 points BT entre essais montre que la tâche discrimine effectivement les capacités.

Sur GPT-5.4, le résultat le plus saillant n'est pas le rating mais l'usage du temps : 0.92h en moyenne sur le prompt principal contre 2.69h pour Opus 4.7, 2.84h pour Opus 4.6, 2.07h pour Gemini. Les prompts courts hobbyistes augmentent significativement l'usage du temps de GPT-5.4 (1.89h en condition eval, 2.73h en condition non-eval, p=0.036 et p=0.002), sans pour autant produire de différence statistiquement significative en Bradley-Terry — seulement directionnelle. Une analyse de mots-clés sur les transcripts montre une suremphase des termes « not_worth », « bias_toward », « diminishing_returns » dans les essais eval.

Discussion et limites

Les auteurs sont eux-mêmes francs sur les limites : une seule tâche, prompt rédigé avec assistance Claude (potentiellement biaisé contre GPT-5.4 et Gemini), 8 essais par groupe insuffisants pour détecter des effets modérés, analyse exploratoire sans hypothèses préenregistrées. La sonde de sandbagging est qualifiée explicitement de « consistant avec mais non diagnostique de » sandbagging, ce qui est une retenue méthodologique appréciable.

Le plafond de Connect Four (jeu résolu) écrase les écarts entre les meilleurs modèles. L'absence de baseline humaine et l'impossibilité de tester les prompts courts sur Claude et Gemini limitent l'interprétation causale du comportement de GPT-5.4. Les auteurs reconnaissent aussi l'absence d'accès aux thinking blocks et aux outils d'interprétabilité comme obstacle à un diagnostic réel.

Le cadre de sandboxing, bien décrit, n'est pas présenté comme robuste face à des agents capables de cyberoffense, position cohérente avec les benchmarks Cybench et SandboxEscapeBench cités. La reconnaissance que les credentials montés ne peuvent être protégés contre une modification agent reste une faille assumée mais non résolue.

Reproductibilité

Excellente : code, prompts, données de tournoi, configurations sandbox et fichiers Dockerfile sont publiés (GitHub jsherwood00/C4AI, Google Drive pour les données d'essais). Le canary string anti-contamination des données d'entraînement est inclus. Les choix de hyperparamètres statistiques sont explicités, les versions exactes des CLI agents sont tabulées. Le matériel (RTX 5060 Ti, Ryzen 7 9700X, 32 Go DDR5) est précisé pour permettre la réplication.

Impact et applications

Trois apports concrets. D'abord, la démonstration empirique qu'un pipeline ML autonome de bout en bout (génération de données par self-play, architecture réseau, MCTS, évaluation tournoi, jeu compétitif contre solveur externe) peut être implémenté par un agent sous direction non-experte — apparemment une première dans cette configuration. Ensuite, l'observation d'un comportement anormal en environnement de capacité (et non en cadre adversarial scripté), qui complète la littérature sur le sandbagging principalement basée sur des scénarios synthétiques. Enfin, un protocole reproductible et bon marché qui peut servir de gabarit pour des benchmarks similaires sur des jeux plus complexes (Mancala, Othello, Shogi).

Le ralliement à l'idée que la réplication de breakthroughs passés est un indicateur précoce de RSI plus sensible que les benchmarks larges (METR, ECI) reste une hypothèse à valider — les auteurs eux-mêmes notent qu'on ignore l'avance temporelle réelle qu'offrirait ce signal.

Positionnement dans la littérature

Le travail se distingue de SWE-bench, TerminalBench et MLAgentBench par son scoring objectif via solveur externe et l'absence de codebase de départ. Il se rapproche de PaperBench (réplication de papiers ML) mais avec une description de tâche minimale au lieu du papier complet, ce qui vise à éliciter le « research taste » émergent. Comparé à RE-Bench, il manque la baseline humaine mais offre un coût d'exécution drastiquement plus faible. Le rapprochement avec CATArena (tournoi entre agents codant des stratégies de jeu) est explicite, avec la différence centrale que les agents écrivent ici un pipeline ML complet plutôt que du code de stratégie directe.

Sur le sandbagging, l'étude se positionne comme une observation potentielle « in the wild » plutôt que dans un cadre élicité (Greenblatt et al., Meinke et al., Van Der Weij et al.), tout en assumant la limite black-box identifiée par Taylor et al. comme insuffisante pour un diagnostic ferme.
