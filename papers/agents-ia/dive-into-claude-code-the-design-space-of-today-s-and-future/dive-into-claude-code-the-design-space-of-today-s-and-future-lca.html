Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems

Lecture Critique d'Article

Objectif et contexte

Claude Code est un agent de codage autonome commercialisé par Anthropic qui exécute des commandes shell, édite des fichiers et invoque des services externes. Son architecture n'est pas documentée publiquement au-delà de la documentation utilisateur. Les auteurs du VILA Lab (MBZUAI) exploitent la disponibilité publique du code TypeScript décompilé (version 2.1.88) pour reconstituer les décisions d'ingénierie du produit.

La question de recherche est claire : quelles réponses concrètes Claude Code apporte-t-il aux questions récurrentes que tout agent de codage doit résoudre (sécurité, gestion de contexte, extensibilité, délégation, persistance) ? Un second axe compare ces réponses à celles d'OpenClaw, une passerelle multi-canal open source, pour tester si le contexte de déploiement conditionne les choix architecturaux. L'ambition est explicitement cartographique : l'étude vise à informer la conception d'agents futurs plutôt qu'à valider empiriquement des hypothèses.

Méthodologie

L'approche est une analyse au niveau du code source, complétée par la documentation officielle d'Anthropic et quelques analyses communautaires. Les auteurs identifient cinq valeurs motrices (autorité décisionnelle humaine, sûreté, exécution fiable, amplification des capacités, adaptabilité contextuelle), treize principes de conception, sept composants fonctionnels et une décomposition en cinq couches. Chaque affirmation est tracée vers un fichier source précis (query.ts, permissions.ts, tools.ts, etc.).

Le protocole présente deux faiblesses structurelles. Premièrement, la méthode est mono-source : les auteurs lisent du code sans entretiens avec les ingénieurs d'Anthropic, sans accès aux discussions de conception, sans commits annotés. Les intentions inférées sont des reconstructions plausibles, non des motivations vérifiées. Deuxièmement, la comparaison avec OpenClaw est choisie opportunément : rien ne justifie qu'OpenClaw soit représentatif des alternatives au-delà de sa disponibilité et de son ouverture. D'autres agents de production (Cursor Agent, Devin, OpenHands) auraient fourni des points de comparaison plus directs mais sont seulement mentionnés en passant.

Résultats principaux

Le cœur du système est une boucle while-true (queryLoop()) de moins de 2 % du code ; les 98 % restants sont l'infrastructure opérationnelle qui l'entoure. Cette proportion, citée d'analyses communautaires, soutient la thèse centrale : Claude Code investit dans le harnais plutôt que dans le scaffolding de raisonnement.

Le système de permissions empile sept couches indépendantes (préfiltrage d'outils, règles deny-first, modes de permission, classifieur ML auto-mode, sandboxing shell, non-restauration au resume, hooks PreToolUse). La logique est deny-first : une règle de refus supplante toute règle d'autorisation, et les actions non reconnues escaladent vers l'utilisateur. Le classifieur ML auto-mode répond à un constat comportemental documenté : 93 % des prompts de permission sont approuvés par les utilisateurs, ce qui rend l'approbation interactive peu fiable comme garde-fou unique.

La gestion du contexte repose sur une pipeline de compaction à cinq étages (budget reduction, snip, microcompact, context collapse, auto-compact), appliquée séquentiellement par ordre de coût croissant. L'architecture d'extensibilité segmente quatre mécanismes à coûts de contexte gradués : hooks (coût nul), skills (faible), plugins (variable), MCP (élevé).

Les sous-agents sont délégués via AgentTool et retournent uniquement un résumé textuel, jamais leur transcript complet. Les transcripts sidechain préservent l'audit sans gonfler le contexte parent. Le coût est substantiel : les équipes d'agents consomment environ 7× les tokens d'une session standard.

La comparaison avec OpenClaw révèle des divergences structurantes : évaluation per-action contre contrôle d'accès périmétrique, boucle CLI unique contre runtime embarqué dans un plan de contrôle, extensions de fenêtre de contexte contre enregistrement de capacités au niveau passerelle.

Discussion et limites

L'étude reconnaît ses propres angles morts : elle n'est pas une évaluation empirique des choix de conception. Aucune mesure n'établit que la pipeline à cinq étages est meilleure qu'une troncature simple, ni que les sept couches de permission préviennent effectivement les incidents de sécurité. Les affirmations sur la supériorité architecturale restent argumentatives.

Le biais de source est problématique. Les auteurs s'appuient sur le code décompilé et la documentation publique d'Anthropic. Or, les commentaires de code sont eux-mêmes produits par Anthropic et peuvent refléter la rationalisation post-hoc plutôt que les décisions initiales. L'étude cite une source (Cherny et Wu, 2025) qui est Anthropic. Le risque de présenter les choix comme cohérents alors qu'ils pourraient résulter d'accrétion organique est réel.

La section évaluative sur la "préservation de la capacité humaine à long terme" reste spéculative. Les auteurs s'appuient sur une étude de 132 ingénieurs (Huang et al., 2025) et un résultat de Shen et Tamkin (2026) montrant 17 % de score inférieur aux tests de compréhension en conditions assistées par IA. Le lien entre ces observations et les choix architecturaux spécifiques de Claude Code n'est pas démontré ; c'est une préoccupation greffée sur l'analyse plutôt qu'un résultat de celle-ci.

La version 2.1.88 analysée est un instantané. Claude Code évolue rapidement, et plusieurs éléments documentés sont derrière des feature flags (HISTORY_SNIP, CACHED_MICROCOMPACT, CONTEXT_COLLAPSE). L'obsolescence du document est inscrite dans son objet même.

Reproductibilité

Les auteurs publient un dépôt GitHub (VILA-Lab/Dive-into-Claude-Code) et référencent des fichiers sources précis. La reproductibilité de l'analyse est bonne : un lecteur peut vérifier chaque affirmation en ouvrant le fichier cité. En revanche, la reproductibilité des conclusions qualitatives (par exemple "la minimalité du scaffolding est un avantage") est faible par nature.

Le ratio 1,6 %/98,4 % AI-logic/infrastructure est repris d'une analyse communautaire sans méthodologie explicite de comptage. Cette métrique frappante mériterait une définition opératoire (ce qui compte comme logique de décision IA, ce qui compte comme infrastructure) que l'étude ne fournit pas.

Impact et applications

L'article comble un vide : il n'existait pas de documentation publique détaillée de l'architecture de Claude Code. Pour les ingénieurs construisant des agents de codage, le document sert de référence directe sur les décisions d'un système de production mature. Les treize principes tabulés (Table 1 de l'article) constituent un cadre utile pour structurer les discussions de conception.

La comparaison avec OpenClaw, bien que discutable dans le choix du comparant, illustre un point méthodologique transférable : les mêmes questions de conception appellent des réponses différentes selon le modèle de déploiement (CLI éphémère contre démon persistant). Cette leçon s'applique directement aux équipes qui portent un agent d'un contexte à un autre.

Les six directions ouvertes identifiées (écart observabilité-évaluation, persistance cross-session, évolution des frontières du harnais, scaling de l'horizon, gouvernance, préservation de la capacité humaine) donnent un agenda de recherche cohérent, même si certaines (gouvernance, préservation) débordent du périmètre technique de l'article.

Positionnement dans la littérature

L'article se situe à l'intersection du génie logiciel empirique et de la littérature émergente sur les systèmes agentiques. Il dialogue avec ReAct (Yao et al., 2022) pour le pattern de boucle, avec SWE-Agent et OpenHands (Yang et al., 2024 ; Wang et al., 2024b) pour les approches d'isolation par conteneur, avec Aider (Gauthier, 2024) pour l'approche rollback-par-git, et avec LangGraph (LangChain, 2024) pour les alternatives à scaffolding explicite.

Le positionnement contre ces systèmes est cohérent mais parfois caricatural : Claude Code est présenté comme l'architecture minimale-mais-défendue-en-profondeur, les autres comme des variantes à trade-offs différents. L'étude manque d'un travail comparable qui appliquerait la même grille à Cursor ou Devin, ce qui permettrait de distinguer ce qui tient à Claude Code de ce qui tient aux agents de codage commerciaux en général.

L'apport principal n'est pas théorique mais documentaire : produire, à partir de sources fermées rendues publiques accidentellement, une cartographie traçable qui survit à l'obfuscation du code. Ce type de rétro-ingénierie structurée pourrait devenir un genre à part entière dans l'étude des systèmes IA propriétaires.
