OCR-Memory: Optical Context Retrieval for Long-Horizon Agent Memory

Vulgarisation

Quand un agent IA stocke sa mémoire sous forme d'images

Un agent IA qui automatise la navigation web sur plusieurs heures accumule des milliers de captures, de clics, de réponses d'API. Tout garder en texte brut sature la fenêtre de contexte du modèle en quelques minutes. Tout résumer fait perdre les détails qui comptent : un message d'erreur précis, une URL exacte, l'ordre d'une séquence d'actions.

Une équipe de l'Université de Hong Kong, de l'Université du Nord-Texas, de Tsukuba et de Yonsei propose un détour inattendu pour résoudre ce dilemme. Plutôt que stocker l'historique sous forme de tokens textuels, ils le rendent en images, puis utilisent un modèle de reconnaissance optique pour retrouver les bouts pertinents quand l'agent en a besoin. Le système s'appelle OCR-Memory, et il améliore les taux de réussite sur des tâches longues d'environ 5 à 10 points face aux meilleures approches textuelles, tout en divisant par près de 7 le nombre de tokens injectés dans le modèle de raisonnement.

Le mur de la fenêtre de contexte

Un agent autonome moderne enchaîne des dizaines, parfois des centaines d'étapes pour accomplir une tâche. À chaque étape, il génère une trace de raisonnement, appelle des outils, lit des résultats, observe l'écran. L'historique gonfle vite. Un GPT-4 standard plafonne à quelques dizaines de milliers de tokens utilisables, et les modèles à contexte long souffrent du fameux phénomène lost in the middle : noyés sous l'information, ils oublient le milieu.

Les approches existantes contournent le problème de trois façons, toutes imparfaites. La récupération sémantique classique (RAG) découpe l'historique en morceaux et fait remonter ceux qui ressemblent à la requête courante ; mais la similarité textuelle confond souvent topiquement proche et logiquement utile. L'abstraction d'expérience compresse les trajectoires en compétences réutilisables ; mais les détails fins disparaissent. La compression de contexte raccourcit le texte directement ; mais on perd des nuances structurelles.

Le défi tient en une phrase : préserver l'intégralité d'une longue histoire sans payer le prix en tokens.

L'idée centrale : encoder le texte comme une image

Les auteurs partent d'une observation récente liée à DeepSeek-OCR, un modèle qui transforme du texte rendu en image en une séquence très compacte de tokens visuels. Une page entière de texte tient dans 64 à 400 tokens visuels selon la résolution choisie. À comparer aux milliers de tokens nécessaires pour stocker le même contenu en texte brut.

L'analogie est simple : prendre une photo d'un livre prend bien moins de mémoire que retranscrire chaque mot, et un humain peut quand même retrouver le passage qui l'intéresse en feuilletant. OCR-Memory applique cette intuition aux trajectoires d'agents. Chaque morceau d'historique devient une image rendue, annotée comme un cahier de notes.

La technique « Locate-and-Transcribe »

Récupérer du texte à partir d'images comporte un risque connu : les modèles vision-langage hallucinent quand l'image est floue ou dense. Les chercheurs neutralisent ce risque par un découpage en deux temps.

D'abord, chaque segment de texte dans l'image reçoit un cadre rouge et un numéro d'identification visible — la technique appelée Set-of-Mark. Le modèle optique ne génère pas du texte libre. Il répond uniquement par une séquence de 0 et de 1, indiquant pour chaque numéro si le segment est pertinent ou non par rapport à la requête. C'est un pointeur, pas une transcription.

Ensuite, une fois les bons numéros sélectionnés, le système va chercher le texte correspondant dans une base de logs textuels stockée à part. La récupération devient déterministe. Aucune hallucination possible : on lit ce qui a été écrit, mot pour mot.

Cette séparation entre localiser (côté visuel) et transcrire (côté texte stocké) est l'astuce qui rend la méthode fiable. Le modèle visuel sert de moteur de recherche ; les logs textuels servent de coffre-fort.

Une mémoire qui flétrit, comme la nôtre

Garder toutes les images en haute résolution coûterait trop cher. Les auteurs s'inspirent de la mémoire humaine, où les souvenirs anciens deviennent flous mais conservent leur sens général. Le système applique une dégradation progressive : les cinq dernières étapes sont stockées en 1024×1024 pixels, le reste passe à 512×512. Une image en basse résolution coûte 64 tokens visuels au lieu de 256, soit quatre fois moins.

Ce qui rend l'idée subtile, c'est le mécanisme de rappel actif. Si une image floue contient finalement un segment pertinent, le système la régénère en haute résolution à partir des logs originaux et la garde nette pour la suite de l'épisode. Les souvenirs utiles redeviennent vifs ; les souvenirs jamais consultés restent flous. Une sorte de filtre adaptatif piloté par l'usage réel.

Comment on entraîne un modèle à pointer plutôt qu'à parler

DeepSeek-OCR sait lire du texte, mais ne sait pas juger quels passages soutiennent une requête. Les auteurs le ré-entraînent sur HotpotQA, un jeu de données de questions-réponses multi-sauts. L'astuce : ils jettent les réponses textuelles et ne gardent que les supporting facts, les paragraphes annotés comme nécessaires pour répondre.

Pour chaque question, dix paragraphes sont rendus dans une image, chacun marqué d'un numéro. Le modèle doit produire une séquence binaire de la forme « 1, 0, 1, 0, 0, … ». La cible n'est plus de générer une réponse, mais de désigner les bons indices.

Quelques choix d'entraînement méritent qu'on s'y arrête. Le encodeur visuel reste figé, seul le décodeur de langage est ajusté via LoRA — on garde intactes les capacités de lecture optique. La fonction de coût pondère plus lourdement les faux négatifs que les faux positifs (poids 2 contre 1) : mieux vaut récupérer un peu trop que rater une preuve. Et les images d'entraînement sont volontairement dégradées à différentes résolutions, pour que le modèle apprenne à fonctionner aussi bien en basse définition qu'en haute définition.

Des gains nets sur des benchmarks longs

L'évaluation porte sur deux terrains exigeants. Mind2Web teste la navigation web généraliste : un agent doit accomplir des tâches comme réserver un vol ou trouver une recette sur des sites variés. AppWorld simule un monde d'applications avec des API à orchestrer, allant des tâches faciles à des cas durs nécessitant beaucoup de retours en arrière.

Avec une fenêtre de contexte mémoire fixée à 4096 tokens, OCR-Memory dépasse cinq baselines, dont les meilleures approches publiées récemment. Sur Mind2Web, l'Element Accuracy passe de 49,1 % (meilleur baseline AWM) à 53,8 %. Le Step Success Rate grimpe à 46,1 %. Sur AppWorld, le score moyen atteint 58,1 %, et l'écart se creuse sur les tâches difficiles : 30,8 % contre 21,4 % pour le RAG textuel classique.

Le vrai test arrive quand on serre la vis. Quand le budget tombe à 1024 tokens, OCR-Memory garde 17 points d'avance sur la récupération textuelle en Element Accuracy. La méthode tient là où les approches textuelles s'effondrent par manque de place.

Une compression réelle de plus de 10×

Les auteurs mesurent aussi la fidélité brute de la récupération sur le test Needle-in-a-Haystack du benchmark RULER : retrouver une aiguille dans une botte de foin textuelle. Le ratio de compression visuelle atteint 10,3× à 4 000 tokens et reste stable à 10,6× à 32 000 tokens. La précision de récupération chute peu : 98,5 % à 4k, encore 94,1 % à 32k. Le système avale du contexte ultra-long sans rendre les armes.

Côté faithfulness, le contraste est frappant. La variante générative qui produit du texte libre obtient 84,3 % de fidélité — autrement dit, près d'un cas sur six contient une hallucination. La variante par index atteint 100 %, par construction : le texte n'est pas généré, il est lu dans les logs.

L'ablation confirme chaque pièce

Retirer les marques visuelles fait chuter les performances et triple la latence. Le marquage par boîte sans index est plus rapide mais moins précis. La résolution fixe haute coûte 256 tokens visuels par image ; la stratégie dynamique en consomme 82 en moyenne, pour un score quasi identique. La résolution fixe basse économise encore plus mais perd 6 points de Step SR. La combinaison adaptative trouve le bon compromis.

Le test de généralisation change le modèle de raisonnement principal de GPT-4 vers Qwen3-32B. Les gains relatifs se maintiennent. Le bénéfice vient bien du mécanisme de mémoire, pas d'une particularité du backbone.

Un déplacement délibéré du goulet d'étranglement

OCR-Memory ne rend pas tout moins cher. Le tableau de coûts publié par les auteurs est honnête sur ce point. Par épisode, le stockage disque passe de 18 Ko à 1,47 Mo — 80 fois plus. La latence de récupération monte de 0,3 s à 1,7 s par étape. Le modèle de vision doit rester chargé en mémoire à côté du modèle de langage principal.

En échange, les tokens textuels injectés dans le contexte de raisonnement chutent de 3 980 à 596 par étape. Soit 6,7 fois moins. La ressource la plus rare dans un agent long-horizon, c'est la fenêtre de contexte du modèle de raisonnement ; le disque et la latence de pré-traitement sont comparativement abordables. Les auteurs assument le déplacement : on échange du cher contre du moins cher.

Pour les équipes qui construisent des agents en production — automatisation web, support client multi-tour, copilotes longs — le calcul peut être attractif. Une heure de session avec un GPT-4 à grosse fenêtre coûte vite plus qu'un peu de stockage S3 et 1,5 seconde de latence par étape.

Ce que la méthode pose comme questions

Le pari conceptuel est intriguant : utiliser la modalité visuelle non pas pour son contenu visuel, mais comme un format de compression dense pour du texte. Les modèles vision-langage modernes deviennent des moteurs de recherche sur de longs historiques.

Plusieurs pistes restent à explorer. La méthode demande un fine-tuning spécifique sur HotpotQA ; tester d'autres jeux d'entraînement, ou voir si un modèle généraliste suffit, serait utile. La résolution adaptative se pilote ici par l'âge du souvenir, mais on pourrait imaginer des heuristiques plus fines : importance détectée, fréquence d'accès passée, type d'événement. Les domaines d'application au-delà de la navigation web et des API restent à défricher : code, documents médicaux, conversations multi-tour très longues.

Une question plus profonde émerge en filigrane. Si l'image se révèle être un meilleur format de stockage que le texte pour des historiques d'agents, on assiste peut-être à un retournement intéressant. Le texte a longtemps été considéré comme la représentation neutre, universelle, du contenu. OCR-Memory suggère qu'à l'échelle des longs contextes, le texte rendu en pixels devient une forme plus économique que le texte tokenisé. Le pixel comme format de compression du langage : voilà une idée qui mérite qu'on regarde où elle mène.
