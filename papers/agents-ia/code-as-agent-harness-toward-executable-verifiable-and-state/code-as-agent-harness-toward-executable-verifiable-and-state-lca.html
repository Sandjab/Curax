Code as Agent Harness: Toward Executable, Verifiable, and Stateful Agent Systems

Lecture Critique d'Article

Objectif et contexte

Le papier reformule la place du code dans les systèmes agentiques contemporains. La thèse centrale : le code n'est plus seulement une cible de génération pour les LLM, il devient le substrat opérationnel sur lequel un agent raisonne, agit, modélise son environnement et vérifie son progrès. Les auteurs nomment cette perspective code as agent harness.

Le terme harness désigne la couche logicielle qui transforme un modèle stateless en agent fonctionnel : outils, API, sandboxes, mémoire, validateurs, frontières de permission, boucles d'exécution. Les auteurs distinguent trois éléments couplés des systèmes long-horizon : capacités internes du modèle, infrastructure de harness fournie par le système, et artefacts de code initiés par l'agent. Ce dernier point — tests de régression, outils temporaires, programmes DSL, workflows exécutables, skills réutilisables — reste sous-exploré dans la littérature, ce qui justifie la synthèse.

Méthodologie

Il s'agit d'un survey de littérature couvrant les travaux jusqu'à 2026. La structuration repose sur trois couches : interface de harness (§2), mécanismes (§3), passage à l'échelle multi-agents (§4), suivies d'applications et de problèmes ouverts (§5). Chaque sous-section présente un ou deux tableaux de systèmes représentatifs avec mécanisme, paradigme et innovation-clé.

Aucun protocole explicite de sélection bibliographique n'est documenté — pas de PRISMA, pas de critères d'inclusion formels, pas de stratégie de recherche reproductible. Le repository GitHub Awesome-Code-as-Agent-Harness-Papers sert de complément, mais reste un agrégat curaté plutôt qu'une revue systématique. Cette absence de procédure formelle constitue une limite méthodologique standard du genre.

Résultats principaux

La taxonomie produite est la contribution centrale. Trois axes structurent l'interface de harness :

  • Code pour le raisonnement : program-delegated reasoning (PoT, PAL), interfaces de vérification formelle (Lean, Coq, Isabelle), raisonnement code-grounded itératif (NExT, CodePRM, RLEF).
  • Code pour l'action : sélection de skills ancrés (SayCan, KnowNo), génération de politiques programmatiques (Code-as-Policies, RoboCodeX), agents lifelong (Voyager, LYRA).
  • Code pour la modélisation d'environnement : représentations structurées (ViStruct, FactoredScenes), modèles du monde par traces d'exécution (SemCoder, CWM, WorldCoder), environnements d'évaluation code-grounded (SWE-bench, AgentBench), construction d'environnements vérifiables (SWE-smith, EnvScaler).

Les mécanismes de harness sont décomposés en cinq catégories : planification (linéaire, structure-grounded, search-based, orchestration), mémoire (working, semantic, experiential, long-term, multi-agent, plus compaction de contexte), usage d'outils (fonction-oriented, environment-interaction, verification-driven, workflow-orchestration), contrôle par boucle Plan-Execute-Verify, et ingénierie agentique du harness lui-même (télémétrie profonde, agents d'évolution, mutation gouvernée).

Sur le passage à l'échelle multi-agents, les auteurs proposent une typologie par rôles (manager, planner, coder, reviewer, tester), modes d'interaction (collaboration, adversariat, débat, red-teaming) et topologies (centralisée, distribuée, streaming).

Discussion et limites

Le cadrage conceptuel est solide. La distinction entre infrastructure prédéfinie et artefacts code initiés par l'agent clarifie un débat souvent confus dans la communauté coding agents. La formulation du code comme medium exécutable, inspectable, stateful donne trois critères opérationnels qui se déclinent bien dans chaque section.

Les faiblesses sont celles du format. Première limite : la taxonomie hérite des effets de mode bibliographiques. Quand un système comme MapCoder apparaît à la fois dans planification orchestration-based et dans multi-agent memory, la frontière entre catégories devient poreuse. Deuxième limite : aucune méta-analyse quantitative. Le survey ne compare pas les performances rapportées sur des benchmarks communs (SWE-bench, LiveCodeBench), ne tente pas d'identifier les facteurs explicatifs des gains, ne discute pas la reproductibilité empirique des claims. Troisième limite : la position défendue dans §4.3 (The Shared Code-Centric Harness Substrate) reste programmatique, sans démonstration empirique propre.

Les auteurs reconnaissent explicitement plusieurs problèmes ouverts : évaluation au-delà du succès final, vérification sous feedback incomplet, amélioration sans régression, état partagé cohérent, supervision humaine, extensions multimodales. Cette section §5.2 est honnête sur les fragilités du champ.

Reproductibilité

Le repository GitHub fournit la liste des papiers cités. Aucune donnée empirique propre n'étant produite, la reproductibilité se réduit à la traçabilité des références — bonne dans l'ensemble, avec des citations numérotées exploitables. Manque toutefois un protocole de sélection formel : un autre groupe travaillant sur le même périmètre construirait probablement une taxonomie partiellement différente.

Impact et applications

Cinq domaines d'application sont passés en revue : assistants de coding (patches, tests, résolution d'issues sur dépôts vivants), automatisation GUI/OS (DOM, accessibility APIs), découverte scientifique (pipelines de test d'hypothèses, automatisation de labo), agents incarnés (politiques exécutables, skill libraries), personnalisation (profils long-terme, politiques adaptatives).

L'apport principal pour les praticiens est conceptuel. La distinction entre code généré comme artefact et code comme harness opérationnel permet de relire des outils comme Claude Code, Codex CLI ou OpenHands à travers une grille unifiée. La discussion sur les fichiers persistants PLAN.md, Implement.md, et sur le harness comme objet filesystem versionnable, formalise une pratique déjà émergente dans les workflows long-horizon.

Positionnement dans la littérature

Le papier dialogue avec les surveys récents sur les coding agents (sur la génération de code, l'agentique LLM, l'ingénierie de skills) en se démarquant par son recentrage sur l'infrastructure plutôt que sur les capacités du modèle. La filiation avec les discussions sur les agent harnesses [13-23] est revendiquée, mais le papier va plus loin en organisant explicitement le code comme axe taxonomique central.

Par rapport à Meta-Harness ou aux travaux sur Natural-Language Agent Harnesses cités en §3.1.4, ce survey joue un rôle d'agrégateur conceptuel plutôt que de proposition technique nouvelle. Sa valeur réside dans la cartographie d'un champ qui a explosé en 2024-2026 et qui manquait d'un référentiel structurant.
