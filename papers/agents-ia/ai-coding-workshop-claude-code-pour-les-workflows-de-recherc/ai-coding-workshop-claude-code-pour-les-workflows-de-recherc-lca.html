AI Coding Workshop : Claude Code pour les workflows de recherche ML

Lecture Critique d'Article

Objectif et contexte

Le document est un support de workshop d'environ soixante minutes destiné aux membres du laboratoire Foreseer de l'University of Michigan. Son objet n'est pas la recherche mais la transmission d'une pratique : comment utiliser Claude Code pour la recherche ML sur cluster HPC (Great Lakes), depuis la prise en main jusqu'à la configuration partagée du laboratoire. La cible est explicitement opérationnelle, organisée en cinq sections : Claude Code 101, principes et bonnes pratiques, usage avancé, configuration partagée du laboratoire, espaces de travail pour agents.

L'auteur positionne d'emblée la rupture générationnelle entre l'ère Copilot (complétion ligne à ligne) et celle des coding agents (portée dépôt complet, exécution de shells, MCP, subagents, browsers, boucle plan-act-verify, délégation d'objectifs). Ce cadrage n'est pas une thèse à démontrer, mais une grille de lecture pour les exemples pratiques qui suivent.

Méthodologie

Aucune méthodologie scientifique au sens strict. Le format est celui d'un guide d'usage structuré autour de trois principes assertifs : (1) le contexte est la ressource la plus précieuse, (2) déléguer plutôt que micromanager, (3) automatiser ce qui se répète (règle des deux occurrences). Chaque principe est instrumenté par des commandes concrètes (/context, /compact, /clear, /agents, /skills, /hooks, /review, /ultrareview, /security-review) et illustré par des exemples HPC : skill /submit-experiment, skill /harvest, hook node-context.sh sur PreToolUse(Bash) qui distingue nœud de connexion et nœud de calcul.

La section avancée propose une discipline de reproductibilité reposant sur quatre éléments : un dépôt unique regroupant code, expériences, papier LaTeX et résultats ; un pipeline scriptable où scripts/artifacts_generation/* lit experiments/ et écrit results/, le .tex ne consommant que des artefacts générés ; un index expérimental à deux niveaux (experiments.md + une fiche <date>_<name>.md par run) ; une séparation explicite faits / hypothèses dans la documentation, avec étiquetage [observed] versus Hypothesis:.

Résultats principaux

Le support n'expose pas de résultats empiriques. Il livre un ensemble de recommandations consolidées qui méritent d'être identifiées comme telles :

  • Une carte des primitives de Claude Code (CLAUDE.md, MCP, skills, agents, hooks) avec leurs cas d'emploi typiques.
  • Une heuristique de gestion du contexte : /compact autour de 30 % d'espace restant, une session par tâche, préférer @file:lines au copier-coller intégral.
  • Le pattern « Goal + verification loop » : énoncer le critère de fin de manière vérifiable (« dev acc ≥ 0.78 »), câbler eval/figure/assertion, demander la commande de vérification dans le plan.
  • L'inversion de l'interrogation (« Before you start, ask me 5 questions to clarify the goal and constraints ») pour les tâches floues.
  • Un modèle de fiche d'expérience avec git hash, commande exacte, version du jeu de données, fichier de log et run ID wandb, hash de configuration, observations et hypothèses séparées.
  • Le dépôt github.com/umich-foreseer/lab-claude-config qui matérialise skills (/onboard, /submit-experiment, /harvest, /slurm-status, /connect), agents (@slurm-queue, @slurm-resource, @slurm-storage) et hook de contexte de nœud.

Discussion et limites

Les forces du document tiennent à sa précision opérationnelle. Les exemples sont datés, exécutables, et le dépôt partagé permet une appropriation directe. La discipline « code controls the paper » avec test de sanité (« supprimer results/, relancer le build, obtenir le même papier ») constitue une formulation nette d'un principe trop souvent flou. La règle de séparation faits/hypothèses dans la documentation, avec « unverified hypotheses go into files only with explicit approval », est une réponse pragmatique au risque de pollution narrative par les agents génératifs.

Les faiblesses sont celles attendues d'un support de workshop. Aucune des prescriptions n'est validée empiriquement : on ignore si la règle des deux occurrences améliore réellement la productivité, si /compact à 30 % est meilleur qu'à 20 % ou 40 %, si la boucle plan-act-verify réduit le taux d'erreur. Les références citées (code.claude.com sections « use-subagents-for-investigation », « manage-context-aggressively », « let-claude-interview-you ») sont des billets de pratique d'Anthropic, non des études contrôlées. La promotion de cmux comme terminal natif d'agent relève du choix personnel (« my favorite right now ») assumé. Le format diapositive avec révélation incrémentale gonfle artificiellement la pagination (40 « slides » incluant des étapes intermédiaires d'une même planche).

L'absence de discussion explicite des risques propres à l'agent autonome sur cluster (consommation de tokens, exécution de commandes destructrices au-delà de ce que le hook PreToolUse couvre, fuite de données via MCP) limite la portée du conseil. La diapositive « No hasty conclusions » traite de l'écriture mais pas des actions irréversibles.

Reproductibilité

Le support est lui-même un objet reproductible : un dépôt GitHub public (umich-foreseer/lab-claude-config) contient la configuration, les skills, les hooks. La phrase « Use this repo to set up my lab Claude Code config on Great Lakes » suffit à démarrer. Cette dimension distingue le document d'une simple présentation orale et justifie le score élevé sur ce critère.

En revanche, les bénéfices revendiqués (productivité, qualité des expériences, discipline reproductible) ne sont pas mesurés, et aucun protocole de comparaison avant/après n'est fourni. La reproductibilité concerne la configuration, pas les résultats de la pratique.

Impact et applications

Le public visé — doctorants et chercheurs ML utilisant Slurm sur Great Lakes — bénéficie directement d'une mise en ordre des primitives Claude Code dans un contexte HPC où la documentation officielle est plus orientée développement applicatif. Les patterns d'index expérimental à deux niveaux et de génération scriptée du papier sont transférables hors du laboratoire d'origine. La codification des trois principes (contexte, délégation, automatisation) recoupe sans la dupliquer la littérature pratique d'Anthropic.

L'impact reste pédagogique et intra-communautaire. Le document n'introduit pas de concept nouveau : MCP, skills, hooks, subagents sont des primitives existantes. Sa contribution est l'intégration cohérente dans un flux de recherche ML.

Positionnement dans la littérature

Le support s'inscrit dans le courant des guides pratiques d'ingénierie de coding agents qui s'est densifié en 2025-2026 autour de Claude Code. Il converge avec les écrits d'Anthropic (référencés via code.claude.com) et avec les retours d'expérience de la communauté sur la gestion du contexte et la délégation. Sa spécificité tient à l'ancrage HPC et académique : Slurm, sbatch, wandb, partitions de stockage Turbo/Scratch/Data Den. Comparé à la littérature scientifique sur l'ingénierie de harness et de skills (Skill-Pro, observabilité de contexte, gating dynamique d'outils), il opère à un niveau différent : empirique, applicatif, sans prétention théorique.
